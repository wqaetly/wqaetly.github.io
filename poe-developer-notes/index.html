一、引擎、渲染与关卡

1. 2011 年的 Alpha 演示：《流放之路》最早怎么生成地牢和森林

原片：《Path of Exile — Level Generation》（2011 年奥克兰开发者聚会）
讲者：Jonathan Rogers 主讲，Rhys Abraham 现场操作编辑器与 Alpha 客户端；配图截自原片，展示的是游戏仍在 Alpha 测试期的早期方案。

2011 年奥克兰开发者聚会这场演示看着挺糙的。当时《流放之路》还在 Alpha 阶段，画面里时不时闪出一串小方块，现场又只有 Rhys Abraham 的笔记本能跑演示，Jonathan Rogers 只好两次提醒台下别管那些雪花。

不过抛开客户端的毛边，他们当年搭出来的随机关卡架构其实已经很成型了。

刷宝 ARPG 有个绕不开的麻烦：玩家换个职业、换身装备，同一张图要反复刷几十遍，怪物和地形要是每次一模一样，跑两趟就背下来了。

但是任务目标又必须找得到，必经的瀑布不能绕丢，森林也得像片真正的森林。Jonathan 开场提的问题很直接：地图里哪些部分可以每次随机变，哪些必须由设计师提前锁住，才不至于连路都走不通（原片 00:17）。

GGG 当年把方案拆成了两条路：

  • 室内地牢：在逻辑图里只管节点连通，用加权最短路打通主线后按门位抽预制房间，适合监狱、洞穴和教堂地牢。
  • 室外荒野：把图上的边直接当成石墙、悬崖、河流或道路的走向，做完节点和边的随机置换、拟合曲线后，再去图块库查表拼接。

两条路做法不同，共用的核心工具其实只有两个：最短路寻路 和按接口查表的 Tile Key。

用 Tile Key 按接口查表拼图块

不管室内还是野外，地图拆到最底下一层都是一块块正方形图块。在01:15 的监狱演示里，一段直墙两侧伸出箭头，标出它能和相邻图块对接的位置。

美术做这类基础图块最费功夫的是接缝精度。引擎会把一块图块旋转出 4 个朝向，镜像翻转后再多出 4 个，一共 8 种摆法，每一种拼上去都不能露缝。

如果墙面上有个很显眼的破洞，转来转去玩家很快就能认出是同一块墙，所以美术得给同一个接口多做几个外观变体。

生成器挑墙时不管具体长什么样，只把四条边的连接布局编成一个索引键，也就是 Tile Key（原片 02:30）。只要条件是南北贯通的直墙，库里所有符合这个 Key 的墙面都会被随机抽中。之后美术再往库里加新墙面，关卡布局一行都不用改。

室内地牢先算最短路再填房间

监狱、洞穴和教堂地牢靠一个个房间拼出来。美术先在房间编辑器里用基础图块搭出方形或矩形房间，摆好宝箱、杂物和刷怪点，再沿着边缘用绿色标出允许开门的格子。有的房间四面都能接，有的只留几个固定门位。

具体要打开哪几扇门，交给逻辑图来定。设计师在图编辑器里把入口房间池 entrance down 连到 Boss 房 boss room，再连到出口房间池 exit out。

如果想让玩家岔出主路去开高价值宝箱，就在主路旁多挂一间宝箱房（原片 03:30–04:29）。图里只规定先后顺序，通往 Boss 房的路到底拐几道弯，交给生成器自己算。

早期的生成算法很朴素，就是从起点出发一间接一间往外摆。Jonathan 回忆，那种做法经常摆到一半就把通往终点的路占死了，剩下的房间没地方放。

网游是在玩家进图那一刻实时算关卡的，总不能摆到最后才发现出口接不上。后来团队反过来做，先保证有路可通，再往格子里填房间（原片 05:16–06:46）。

具体分三步：

  1. 从逻辑图里取出一条边，定好入口和 Boss 房两端的位置，按可用房间尺寸把中间划成网格，Boss 房到出口那段照搬一遍。
  2. 给每个格子随机分配通行代价，调试视图里绿格好走、红格代价高。
  3. 在连通网格上求起点到终点的最低代价路径。

因为网格本身是连通的，最短路一定能找出来，为了绕开高代价的红格，路线自然会弯弯绕绕，不会是一条死板的直线。

沿着算出来的主路在相邻格子间标出门位，主线就成型了，之后再按分支系数在主路旁边长出支线房间和死胡同。

等每个格子的尺寸和开门位置全都敲定，生成器才去房间池里抽符合条件的预制房。就算连续两次抽中同一间，叠上旋转、翻转和房间内部的图块变体，玩家也很难一眼看穿。

洞穴通道靠这套房间算法还能应付，但到了室外，设计师要管的是河道拐弯和林间石墙的走向，拿方形房间硬套就不合适了。

室外地图用折线生成石墙、悬崖和河流

室外地图照样从图编辑器起手，区别在于图上的边直接对应具体地貌，比如石墙、悬崖、河流或者道路。

Rhys 在编辑器里横着拉了一条代表石墙的直线，每点一次重新生成，这堵墙就会换一条弯曲轨迹横穿地图（原片 08:31–09:17）。

切进分步调试视图，能看到这堵直线变弯的过程分两步：

  1. 宏观节点置换（Macro Node Permutation）：把折线的端点和拐点随机挪位置。
  2. 宏观边置换：把边切段、撒随机权重，再用最短路把节点重新连起来。

原本笔直的一根线，走完这两步就有了自然起伏的走势。

接着要拼图块。室内图块每条边只有一个接口，放到弯曲的石墙和河岸上太生硬，所以室外图块在正方形每条边上留了上、中、下 3 个连接点。

对称的双面墙算上旋转和翻转，大概 10 块基础图块就能应付大部分转弯，三岔和四岔路口再另做接头。

换到悬崖，件数就得往上涨。双面墙两面一样，悬崖却分高地和低地，把一个拐角旋转或镜像，形状看着对上了，高台却翻到了另一边。

算上高低过渡，一套悬崖一共需要 18 种连接组合。Jonathan 在台上先脱口报了 16 种，转头问了 Rhys 一句才改回 18。

画悬崖线时，设计师必须标清哪边高、哪边低，演示里拿它封住了地图一侧，画在地图正中间也没问题。

落到拼图环节，引擎先把折线拟合成贝塞尔曲线，看曲线离网格边缘 3 个接口里的哪一个最近，凑出 Tile Key 再去图块库查表（原片 10:15–12:00）。

河流的麻烦又不一样，因为河有左右两岸。要是在编辑器里直接画两条独立的河岸线各自随机抖动，两条线很容易撞到一块把河道夹断，或者越漂越宽。

团队的办法很省事：先拿一根单线代表整条河，照常跑宏观节点置换和边置换。等河道走向定下来，进入剖分阶段（Splitting Phase），沿折线法线向两侧各偏移一段距离劈出左右两岸，修圆拐角后再往中间填水（原片 12:31–12:45）。不管河道怎么拐，两岸的宽度和走势都能保持一致。

Voronoi 防越界和两种路口交叉

节点能随机移动，立马会引出一个拓扑隐患：假如原本在河东的节点被挪到了河西，连着它的那条路就会莫名其妙多跨一次河。

引擎的防线是 Voronoi 单元。生成器先按离哪个节点最近把整张图划成一块块区域，每个节点只能在自己那块区域里活动。如果单元里已经有连线穿过，节点还得待在线的同一侧（原片 13:30）。这样不管怎么随机，设计师画在河西的路永远留在河西。

当然，有些交叉是设计师故意要的。Rhys 在台上添了一条从左侧进图、先过河、再穿石墙中部、最后从上方出去的道路。从14:46–15:30 的调试画面里能看出，这两种交叉的处理时机完全不同。

  • 路过河是在宏观阶段放桥：生成器直接把虚拟河流边和道路边的类型合进 Tile Key，查表正好命中现成的桥梁图块。
  • 路穿墙则要拖到剖分之后再接路沿：图块库里没有整条宽路直接穿墙的块，生成器先照常算出道路走向、修圆拐角，沿法线把有宽度的路拆成左右两条路沿。拆分完再看交叉口，石墙左右各碰上一条路沿，两边各用一块小接口图块就接上了，路中间自然留出豁口。

植被、调光与演示机上的雪花 Bug

大骨架定完，给森林铺细节分三层往上加（原片 16:00–16:39）：

  1. 撒树木和小土丘（调试视图里树顶那块黑影，是因为镜头架在树冠底下，抬头看成了树冠投影）。
  2. 按块状规则铺地表贴图，土丘这类特殊地貌配专属材质。
  3. 撒灌木、枯枝和杂草这类零碎装饰物。

切回客户端后，两人拉出环境参数面板，现场改光照方向、阴影和雾效，还故意把光调成亮粉色好让台下看清变化，随后切回正常预设（原片 17:15）。

前面提到的雪花噪点贯穿了大半场演示，Jonathan 台上先后请大家先别管它，问答时也交代清楚了：这毛病只在 Rhys 这台笔记本上出现过，偏偏当天只有这台机器拿来演示，还没来得及排查（原片 18:30 / 21:08）。

讲到尾声，他顺带招起了 Alpha 测试玩家和美术，用他的原话，是来帮忙喂这台图块绞肉机（meat grinder of tiles）。

现场问答记录

有人问大型地标能不能定点放。可以，演示地图角落通往下一关的战堡入口就是指定的特殊图块，这类地标费工，一般没几个变体。

要是只需要一小块固定场景，还可以先在室内编辑器里做好整间房，当成一块超级图块嵌进室外地图，Boss 营地就是这么做的（原片 19:40）。

至于会不会放编辑器做 Mod、支不支持局域网，两个答案都是不行。Jonathan 直说这是纯在线服务游戏，不设单机模式，没法把编辑工具发出去。

聊到局域网时，他把免费商业模式也直接摊了出来：所有玩法内容完全免费，只靠火焰剑特效、宠物这类外观微交易和切服等少量便利服务赚钱，必须由官方服务器托管，没法支持离线联机（原片 19:16 / 21:31）。

还有人问地图上既然有悬崖，引擎到底是 2D 还是 3D。核心玩法留在 2D 平面，后台同步维护一张高度场。把大部分计算按在 2D 上能省掉很高的开发复杂度，图块本身带高度数据，上下层靠高低过渡块衔接。

Rhys 专门切到梯田地图找了处斜坡演示，Jonathan 补充说高度场确实参与物理和弹道碰撞。现场角色没带火球，不过真对着悬崖丢火球，它会按三维轨迹撞在崖壁上炸开，不会贴着二维地板穿墙飞过去（原片 22:46–23:45）。

2. ExileCon 2019 地形专场：《流放之路》十一年的随机地图演进

原片：ExileCon 2019 第二天地形专场与问答
讲者：Rhys Abraham；时间背景为 3.9 版本上线前、《流放之路 2》仍称作 4.0 原型的阶段，配图截自原片。

关卡设计师在编辑器里贴着一面平墙摆好了沙发，结果进游戏一看，一根石柱直接从沙发正中间穿了出来。Rhys Abraham 在 ExileCon 2019 讲地形生成时，就是拿这个常见事故开的头（原片 00:30）。

Rhys 2008 年刚从奥塔哥大学计算机系毕业，就进了 GGG 当初级程序员。那会儿克里斯的车库里本地成员只有六七个人，交给他的第一份活就是写随机地牢生成器。几个月后亲友在圣诞派对上玩到 0.2.0 版，画面里还有法线贴图反掉的地方。

十一年过去，这套 C++ 地形代码滚到了数万行，管着游戏里超过 1000 个区域、约 15000 块地形砖。从神龛、瓦尔侧区、迷宫、异界图鉴，到深渊、穿越、地心、背叛、虚空忆境和菌潮，几乎每个大机制上线都要改一次生成器。演讲时，团队还在往里加《流放之路 2》（当时叫作 4.0 原型）的新试验。

Tile、Tile Key 和房间文件

海滩、森林、城镇、异界地图，全是一块块地形砖拼出来的，大多是正方形，偶尔有长方形。

环境美术先在 Maya 里做低模，拿蓝色的连接轮廓线对齐接缝，保证两块砖挨在一起不留缝隙。模型通过自定义导出器进引擎后，关卡设计师再打开 C++ 写的 Tile 编辑器，标出地面类型、边缘类型和连接点，同时画出可行走网格和高度网格（原片 03:50）。

编辑器的网格视图如下，右侧用绿、黄、红三种颜色区分物理规则：

  • 绿色：正常可行走的陆地。
  • 黄色：走不上去的区域，比如水面和部分陡岸。
  • 红色：大树或高墙这类高耸地形，走不过去，也会挡住投射物，连跃击都跨不过去。

在静态网格之上，引擎底层早就支持运行时动态开关碰撞阻挡，最常见的用法就是开关门。

现场有玩家问，能不能让冲锋怪把树撞断、撞出一条新路。Rhys 说一代第二章时他们真设想过让吞噬者（代码里至今叫 root spider）撞碎大树破土而出，当年太费劲就搁置了，具体哪个版本他自己也记不清。

现在底层技术已经齐了，主要卡在玩法设计上：这种场景破坏得足够高频、真能左右战术才有意思，偶尔碰巧撞断一棵树意义不大（原片 44:02）。

生成器挑砖时只认 Tile Key，不认具体资产名。这个索引记着砖的尺寸、四条边怎么接邻居、四个角各是什么地形。拿上面那块河岸砖来说，两个角在水里、两个角在陆上，河岸顺着边缘延到下一块砖。生成河流时，引擎先用方形 Tile Key 贴合样条曲线，等连接点全对上了，再拿这些 Key 去库里抽砖。

同一个 Tile Key 底下可以挂好几块外观不同的砖，也就是微变体。美术只要守住边缘的连接轮廓线不动，砖面上长什么草、墙面上有没有浮雕，都可以自由发挥。

光靠单块砖拼复杂结构太零碎，所以系统在 Tile 之上一直留着早期地牢时期的房间概念，室内地牢和室外营地（像赤红谷入口）都在用。房间里通常会标出门位，等生成时按需要再刷门，不会一开始就把门砖写死，同时也能提前放血迹贴花、杂物、怪群、宝箱和任务道具。

开头那桩穿模事故就出在存储方式上：房间文件里存的是 Tile Key 阵列，具体抽哪块模型要到进图生成时才定（原片 05:43–05:47）。

设计师在编辑器里挑了面平墙，贴墙摆好沙发；进游戏后引擎按同一个 Key 换了另一块微变体砖，边缘接缝完全对得上，多出来的装饰石柱却刚好扎进了沙发正中央。

室外图、地牢图和叠掉一格墙的做法

拉远到整张区域，起点是一张由节点和边组成的图。不过同样一根线，在室外图和地牢图里意思完全两样。

室外算法负责河流、悬崖、海岸线这些自然地貌。图上的边直接对应河流、森林、悬崖或泥穴兽轨迹等实体地形，因此边不能交叉。

设计师先放好入口、出口、Boss 战、任务点和交汇点，再给每条边指定含义（蓝边河流、绿边森林、灰边砍伐林、棕边泥穴兽轨迹）。具体生成分四步（原片 07:31）：

  1. 随机扰动节点位置。
  2. 在加权网格上沿每条边寻路。
  3. 把路径转成样条曲线，用方形 Tile Key 逼近并抽带微变体的砖。
  4. 填满封闭区域里的空当，水面和密林直接平铺，可行走空地填进随机填充砖或填充房间。

地牢图宽容得多，边表示的是房间之间的连通关系或裂隙走廊，可以直接十字交叉。拿《流放之路 2》的墓穴举例，黑边是深渊裂隙线，粗灰边是主通行路径，两条线直接穿在一起，生成器最后只要挑一间能同时满足所有连接方向的房间就行（原片 09:45–11:46）。

方房间一间挨一间摆，最怕露出太重的格子感。GGG 的做法是让相邻两间房的边缘重叠 1 个 Tile Key 的宽度，不让它们硬贴在一起（原片 12:45）。

这时候引擎还没放具体模型，可以先按规则把重叠的两个 Key 合并成一个新 Key，再去挑砖：

  • 两个背靠背的厚墙 Key 叠在一起，合成一道单层薄墙。
  • 定义 墙 + 墙 = 空地，隔墙就能直接消掉，把两间小房融成一个大空间。
  • 配合自定义重叠规则，除了纯野外自然图，复杂场景基本都离不开这套机制。

一代第四章矿坑里的矿车轨道、深渊、木平台，就是靠自定义重叠规则咬合的。

二代试玩结尾的燃烧村庄更进一步：森林和麦田间散落着残破农舍，设计师给建筑边缘定了两三种损毁程度，两个房间一重叠，生成器就按边缘类型挑一段合适的残墙（原片 14:15）。每次刷进村，房子的破法都不一样，底下主路照样由地牢图兜底。

20 毫秒预算与双端校验

节点挪来挪去、房间互相重叠，难免撞出接不上的死局。服务端在放人进图前会先跑一遍校验，查接口齐不齐、入口到出口通不通。

比如下面这个失败案例，中部两间房靠得太近、放不下必需的连接边。遇到这类几何或拓扑冲突，服务端干脆换个随机种子整张图重算（原片 16:01–16:35）。

程序员当然可以多写一套算法去把太近的房间推开，可跑一次整图生成才 20 ms 左右，推倒重来既稳又省事。

为了不让玩家卡读条，自动化测试一直在盯全游戏 1000 多个区域的单次生成成功率：

  • 绝大多数区域都在 90% 以上。
  • 掉到 60%～70% 以下就会触发报警，演讲时大约有 30～40 个区域和子图偏低，旧版第三章占了几个，后台日志报错最多的是菌潮地图。
  • 全游戏没有任何区域跌破 30%。

服务端验过关后，只把种子发给客户端，客户端照着一模一样的规则自己算一遍，然后双端分别对最终砖块排布算哈希值。

只要两边哈希对不上，玩家就进不去图，屏幕上弹出一句 terrain generator is out of sync。哈希只告诉你结果不一样，不告诉你哪一步分叉了，Rhys 说撞上这种问题往往得翻成堆的日志慢慢查（原片 17:34）。

因为固定种子能原样复现一张图，团队围绕它攒了一批排查工具（原片 40:45）：

  • 开发者遇到怪图，按 F4 就能把当前关卡导进外部 C++ 工具里反复跑、看日志（只有少量辅助工具用 C# 写）。
  • 玩家在聊天框打 /bug（3.7.0 起支持附文字说明），后台会记下种子和关键状态，自动拼一段作弊脚本。程序员复制过去本地一跑，就能站在玩家出事的同一张图里。

光照系统也接进了这套体系。早期一张图只能绑一套写死的全局灯光；演讲前几年重构后，设计师可以划出自定义光照包围盒，不同房间各用各的照明，玩家跨界时平滑过渡。Boss 出场时切音乐、变灯光也可以走这套机制，现场试玩里的锈王大概就用了它（原片 35:17）。

自动化构建还会盯每张图的几何面积、怪量、宝箱和预期掉落。刷怪和宝箱分两种放法：

  • 按房间手动埋点：局部密度稳，但大图总怪量容易偏多。
  • 按总量随机撒：收益好控制，可小图容易挤成一团，大图又显得太空。

终局异界地图一般选定死总怪量，再把面积波动压在目标值的 ±10%～20% 内，早年海滩那种一条直线刷到底的热门图，就是这么被针对性调整布局的（原片 30:21 / 50:15）。

至于藏身处，因为玩家摆装饰经常会特意对齐一丛草或一块地砖缝，所以连纯外观的微变体都不允许随机换，直接锁死种子，免得下次上线或导入模板全错位（原片 51:25）。

线上常见地形 Bug 与赛季踩坑

玩家在游戏里撞见的地形毛病很多，比如看得见却捡不着的掉落物，排查下来基本分两种情况（原片 27:15）：

  • 美术手绘 Tile 可行走网格时，在阻挡区中间漏画了一小块孤立的绿格，装备能掉上去，角色用跃击、闪现射击都够不着。
  • 怪物跃过深渊时在半空被打死，掉落物直接按死亡坐标刷在深渊上头，这就得去修玩法代码。

背叛赛季进不去的辛迪加要塞，则暴露了存量老图的包袱。要塞占地比以往任何机制都大，可当时全公司只有 4 名关卡设计师，不可能手动改完上千张老图，程序只好写了一套自动腾空地的算法。

结果 3.8 版本这套算法出现了退化。Rhys 讲了个很现实的情况：4 个设计师拿同一个生成器搭了一千多张图，不少老图其实暗中依赖了生成器早年的某些怪癖，程序一修 Bug，原本好好的老图反而生成失败了。演讲时他们打算在 3.9 集中清这笔账（原片 36:16）。

地心矿坑则是另一种约束。矿坑相邻格子经常属于不同生态，两套完全不同的地形叠一格也融不到一起，只能靠美术专门做生态过渡砖。

矿坑实例原本统一是 5×5 大格，每次从城镇或藏身处进营地重新生成，后来为了放得下超过 5 格的超长路径，才破例扩出 8×4 这类矩形网格。

团队也讨论过走到网格边缘直接点门继续往深处走，推演完放弃了。走亮着的老路本来就能直传矿车；真要摸黑探路走到边缘，读条那几秒算不算在黑暗里掉血、给不给无敌、反悔回头怎么算，边界条件太折磨人（原片 47:32）。

至于全游戏无缝切图，2019 年时引擎还没有流式资产加载，也不能像单机动作游戏那样拿慢吞吞的电梯或之字走廊偷偷卸载背后场景，短期内不现实。不过 4.0 新内容里，团队已经砍掉了沿用多年的纯白硬切过场（原片 46:30）。

2019 年的《流放之路 2》地形原型

除了维护一代，Rhys 还展示了当时给《流放之路 2》做的几项新试验。一代存量的 1000 多张老图改造代价太大，这批新技术基本只进二代，只有 Tile Overlays 这类通用工具会回流给 3.x 新区域（原片 32:17）。

按角色 ID 随机的世界地图与城镇出口

在 2019 年的原型里，连世界大地图都改成了程序化生成，种子直接绑在角色 ID 上（原片 18:07–18:37）。同一个账号新建角色，世界地图的方位就会洗牌，再也没法背“庄园永远在村庄北边”。

城镇里哪扇门能走直接跟着世界地图变。比如 Clearfell 刷在城镇右下方时，城里同步打开右下角大门，客户端把其余备用出口用木箱杂物堵住，能走的那扇门框亮起 Erik 做的发光特效：

组队时按谁的地图算当时还没拍板，初步倾向以队长为准（原片 29:32 / 33:46）。

单边 3×3 道路与模式匹配覆盖层

一代画路是用两条边分别表示左右路沿，两边各自寻路，拐起弯来间距很难稳住，动不动挤成一条细缝或者突然变宽。

二代原型改用一条边代表整条路，路砖也从 1×1 格扩到 3×3 格，一块包住两侧路沿。宽度稳了，可拐弯成了死板的直角，于是生成器再跑第二遍，用模式匹配算法把直角挑出来，换成接口相同、路面带弧度的弯道砖（原片 21:09–23:08）。

这套模式匹配后来又扩展出了 Tile Overlays（覆盖层房间）：主图先出大边，再沿边自动找能叠放局部特征的位置。白框标出的区域就是沿主边自动贴附的覆盖层：

拿河道举例，以前连断桥都得一座座手标；现在设计师只要定死一座完好的桥保证能过河，其余河段由系统随机贴完好的桥或者半截断桥。

3. ExileCon 2019 渲染笔记：Alexander Sannikov 讲《流放之路》的图形演进

原片：《Evolving Path of Exile’s Renderer》（ExileCon 2019）
讲者：Grinding Gear Games 高级图形程序员 Alexander Sannikov，动画师 Sam 主持问答；演示包含已上线效果与早期原型（当时二代仍称作 4.0.0），配图截自原片。

给《流放之路》写图形算法，没法按“玩家老老实实放一个技能”来算开销。Alexander Sannikov 一上台就点了一串老玩家很熟的名字：高阶多重投射、Sire of Shards、法术涟漪，还有著名的 Wormblaster。

单个技能特效画起来本来挺便宜，一旦被玩家铺满整个屏幕，压力完全是另一回事。更麻烦的是主机和低配 PC 也得跑得动，新算法还得直接插进现有的前向渲染管线，为了某一个效果把十几年攒下的旧资产全迁到延迟渲染，代价实在太大（原片 01:15–01:32）。

好在《流放之路》也有自己的优势，尤其固定俯视角给了渲染团队不少余地（原片 08:15–09:01）：

  • 很多问题直接读屏幕上已经画好的像素就能算出靠谱的近似解，丢给 GPU 算，不抢 CPU 处理战斗的算力。
  • 地图是图块动态拼出来的，水流流向这类数据可以等拼完交给空闲线程去算。
  • 静态不变的数据，甚至能在玩家下载客户端前就离线算好。

聊起日常研发，Sannikov 挺坦诚：很多点子在白板阶段就被毙了，真写成原型的也大多没进游戏。但他觉得这时间花得值，不试一遍根本不知道哪种近似会在哪儿穿帮，后面上线的流体模拟就是他业余写出来、反而进了主项目的例外。

问答里有人请教接新需求前怎么调研，他的建议也很直接：平时就多写小实验，包括那些看着不太可能成活的（原片 48:32）。

迁到 PBR 之后，伊泽洛不再在红灯下发光

GGG 前后花了五年，才把整套引擎慢慢迁到 PBR，当时定在 4.0.0 收尾。把 Phong 高光换成 GGX 只是表面一步，对《流放之路》这种高度复用怪物和场景的游戏来说，PBR 最大的好处是材质属性和灯光解耦。

美术只管定义这是一块金属，怪物搬到另一张图里换了光色和亮度，看着还是金属。自研的 Asset Viewer 和第三方工具 Marmoset 预览结果一致，验收外包资产也省心多了。

迷宫 Boss 伊泽洛就是个直观的反面教材。老版本里玩家只在帝王迷宫固定的环境光下见他，美术顺着那个房间的灯光逐项硬调材质，不少参数在物理上压根不合理。

留在迷宫里倒相安无事，可只要把灯换成红光，他浑身立马泛起诡异的红晕，拖进阴影里该暗下去的部位甚至像自带灯泡一样在发光（原片 02:17–05:03）。

幻灯片上那句 Safe Driving Practice in Rendering 挺贴切：守交规不保证你开车有多帅，但至少能平平安安开到地方。按物理规律调材质也一样，单看某一帧未必更惊艳，换个房间却不会出伊泽洛这种事故。

迁移完旧资产后，摄影测量扫出来的地面贴图几乎不用手修就能直接用，写潮湿地面 Shader 也省事多了（原片 06:46）。

矿坑点光源软阴影（SSHVSM）

判断地上一个陶罐是踩实了地面还是飘在半空，全看接触阴影。贴着罐底那圈半影很锐利，离罐子越远，影子边缘越发虚。

传统阴影贴图碰到这种场景有两处难顶：先画硬影再模糊，很容易把整条影子糊成一样宽的软边；想让远处更软就得放大模糊半径，最费算力的偏偏是远处那段。

更要命的是矿坑里的点光源朝四面八方照。平行光一张图够用，点光源得画立方体贴图六个面，十盏灯就得把场景几何重画十遍。

到了地心探索赛季，Jonathan Rogers 还定了硬指标：矿坑玩法就靠黑暗里的灯光撑着，设置里不让玩家关阴影。也就是说，这套软阴影必须连低配机器都全程扛得住（原片 12:31–13:33）。

Sannikov 的解法叫屏幕空间层级方差阴影贴图（SSHVSM），直接读屏幕上已经画好的像素，不再为阴影重新提交几何（原片 14:18–16:42）。

它的分层思路很清楚：近处接触阴影边缘最锐，用最高分辨率算，但覆盖面积很小；远处半影占地虽大，本来就是糊的，用低分辨率 MIP 层级就够描述。各层级算力大致均衡，最后结合深度做上采样避免轮廓出现方块锯齿，再轻扫一次单像素模糊，影子就由实到虚自然晕开了。

更关键的控预算手段是数量封顶：每个受光点只挑 2 盏主要光源算阴影，屏幕里亮 100 盏灯也不会把开销乘以 100（原片 17:15）。Sannikov 现场举了个极端例子问观众选哪个：平时 300 FPS、偶尔掉到 5，还是稳稳待在 60 到 100？这组数字只是举个极端例子，用来说明为什么要卡死最坏情况开销。

这套方案的代价也很明确，屏幕外的遮挡物算不到。固定俯视角下玩家基本察觉不出来，换到能甩镜头的射击游戏马上就会穿帮。

3 毫秒硬预算里的屏幕空间全局光照

看楼梯对照就能直接看出间接光的差别。一打开，受直射光照亮的台阶会把光弹到背光面，原本死黑的角落透出层次；画面下方的龙贴着自发光材质，周围压根没摆灯，地板照样染上一片蓝（原片 19:10–20:44）。

引擎在屏幕空间里估算像素对周围的辐射贡献，省得满地放带阴影的假灯。这功能在设置里可以关，舞台演示默认开着。

按渲染方程写离线路径追踪器，核心代码十几行就行，代价是渲一帧花五小时。留给《流放之路》的 GI 预算只有 3 ms，而业界常见的三种思路在 2019 年都行不通（原片 22:32）：

  • 时间重投影：角色和投射物飞得太快，借上一帧数据补这一帧，拖影太明显。
  • 离线烘焙：关卡由图块随机拼接，烘焙时压根不知道谁跟谁挨着，算不出跨图块反弹光。
  • 硬件光追：当时没法指望人手一张 RTX，而且这套专用算法在那时比硬件光追还快。

既然要在一帧内算完，又不能加采样数和指令数，就只能改采样分布和读法。普通的指数采样画出来满屏放射状条纹，Sannikov 用三步把条纹抹平，GPU 算力消耗和最初满是条纹的版本一样（原片 24:49–26:20）：

  1. 做 4×4 抖动偏移，让相邻像素错开随机偏移。单像素采样数不变，但邻居不再扎堆采同一个方向。
  2. 过一遍 4×4 盒式滤波，把抖动换来的高频噪点平均掉。
  3. 给深度缓冲和颜色缓冲建 MIP 层级（Mipped Depth），看远处反射光时读粗层级，一次采样就能拿到一大片的平均深度和颜色。

这套屏幕空间全局光照（SSVHBGI）和前面的 SSHVSM 一样 100% 跑在 GPU 上，不抢 CPU 算战斗的时间（原片 27:19）。

一次纹理采样画出浑浊冰晶

军团赛季满地都是冻着怪的半透明水晶。引擎本来就有屏幕空间光线追踪折射，台上也演示了水做的圣堂武僧和冰块里的伊泽洛。

可真放到冰晶上反倒不对味：逐像素步进追踪太贵，算出来的质感还像透明玻璃，里头的伊泽洛清清楚楚，少了冰和玉石内部散射出来的浑浊感。

于是有了次表面折射（Subsurface Refraction）。Sannikov 拿“邪恶土豆”测试模型试了个近似假设：表面底下藏着一层次表面，两层之间的深度处处相等。

深度固定后，折射光线打在次表面上的 UV 坐标直接一步算出来，取颜色只需要 1 次纹理采样，画块军团水晶的开销跟画它脚下的普通地面差不多（原片 28:45–29:53）。

更有意思的是，同一张次表面贴图预先生成 MIP 层级：画清透冰晶读高清层，画浑浊冰块读粗糙层，拿局部平均色模拟内部散射。粗层级分辨率小、GPU 缓存命中率更高，结果在这个 Shader 里，浑浊的冰反而比透明的冰更便宜。

后来艺术总监 Erik 给宣传片结尾要一片暴风雨海面，水面 Shader 直接借了次表面折射加厚度图来表现透光海浪。菌潮赛季早期试过的软糖状黏液原型也是它的衍生品（原片 31:00）。

地图拼好后，让空闲线程去算水流

一聊流体模拟，玩家通常会担心占用 CPU 影响战斗。Sannikov 自己读博时就爱研究流体力学，放进游戏前先立了规矩：纯视觉效果只蹭 CPU 空闲时间，放后台线程求解，切图和下一帧渲染全都不等它。

地形数据本来就标好了哪里是水，美术只需要补两个点：出水口和汇水口。

哪怕把同一块森林图块转个方向，或者放到第三幕大坝上，后台的代数多重网格求解器（Algebraic Multigrid Solver）都能比常规迭代法更快算出贴合当前拼法的流场（原片 32:31–33:32）。

算完以后，CPU 交给 GPU 一张流向图，记着各处流速和方向。水面 Shader 照着图推纹理，流速落差大的地方叠加白沫，之后每一帧直接复用这张图，再也不用重算（原片 35:16–35:30）。他也提到，这套后台求解器以后拿来算雾的流动同样合适。

一亿多边形的草地，压进 1 MB 贴图

如果把演示里狩猎场的每根草全建出模型，大概需要 1 亿个多边形，是当时 60 FPS 下整帧预算的一百倍。换常见的半透明草片虽然省了面数，可草片层层叠叠，同一像素被反复画，Overdraw 很高，造型还得一根根抠。

Sannikov 干脆把最贵的几何光线计算全推到离线阶段（原片 36:18–38:50）。核心简化藏在几何假设里：如果草叶满足竖直对称的约束，三维光线投射找交点的问题就能退化成等价的二维平面光线投射。

这么一拆，就可以提前离线算完各个视角会打到哪片叶子，结果全烘进贴图里。第一版原型外号叫“无限面条”，看着是一大团密集的立体条状物，其实一根多边形都没画：每个像素只查一次纹理，时间复杂度 O(1)，草种得再密也不会掉帧。

早期版本看着不太像草，同事有的说像海藻，有的说像染绿的毛。等颜色和叶形调顺眼了，铺在地上又一眼看得出贴图平铺的重复感。

团队加上 Texture Bombing，平铺时给纹理加随机偏移和变换，没加计算量也没扩贴图，重复感明显淡了（原片 39:31–41:34）。

后来狩猎场和墓地用的就是这套草，连边缘抗锯齿都是烘焙时算进去的。打包出来的贴图才 1 MB，代价全吃在离线机器上，跑一次要 72 小时。Sannikov 的习惯是周五下班前按回车，过完周末回来验收改了参数的新草皮。

忆境、异界图鉴和深渊的三个赛季解法

忆境关卡崩解：走后处理，不碰材质库

Jonathan 当时想把整张地图一点点吞噬销毁。写个溶解 Shader 不难，可一旦放进材质层，游戏里每一种旧材质都得拆成正常版和销毁版两份，往后维护的 Shader 直接翻倍。

团队改在后处理里做：地图照常画，最后在屏幕上叠空间撕裂和地面塌陷。地面裂纹则是 Sannikov 写小程序模拟油漆干裂拉扯生成的（原片 42:30–43:20）。

异界图鉴裂界者势力：标量场实时抽轮廓

异界图鉴里裂界者的势力范围是在打开界面时实时算出来的，演示里不到 10 ms。算法给受影响节点赋标量势，再做标量场矢量化（Scalar Field Vectorization）抽轮廓、平滑曲线，测试时拖一下节点，触手就会拉扯融合。

后来海浪涌向岸边需要平滑海岸线，团队直接复用了同一段代码（原片 43:55）。

深渊裂缝：直接改深度缓冲

深渊裂缝刷在哪儿都没准，连水面都得裂开。引擎不切地面网格，直接改写深度缓冲，把裂缝里的像素改成坑底的深度，坑就凭空凹下去了（原片 45:46–45:58）。

现场他还给坑底开了实验版 GI，另外放了两段没照原样上线的片段：一段是失控烧满全屏的火，另一段是没绑挂点、被烈焰爆破直接炸飞的机械翅膀，上线前 Erik 要求把飞散距离调小。

4. 重看 ExileCon 2023：Alexander Sannikov 讲《流放之路 2》的渲染

原片：《Rendering Path of Exile 2》（ExileCon 2023，52:56）
讲者：Alexander Sannikov（GGG 高级图形程序员）；文中耗时和粒子数量均为现场估算，配图截自原片。

2023 年 ExileCon 上，Alexander Sannikov 用五十多分钟拆解了《流放之路 2》渲染器里的一批核心做法。前面聊的都是很具体的画面和工具问题，比如熔岩怎么流才不拉丝、浑水怎么用 2D 贴图做出纵深、拍岸浪怎么卡住参数不崩。

后面则是他首次公开的一套实时全局光照方案。当时演讲里叫辐射度探针层级，也就是后来在图形学社区传得很广的 Radiance Cascades。

流动材质怎么打散重置节拍

像熔岩、河水这类一直流动的表面，最直接的做法是用一张速度图每帧推着 UV 走。问题在于液面各处的流速和方向不一致，有的区域往外发散，有的区域存在剪切，跑上几秒，原本清晰的花纹就会被扯成细丝。

常见的补救办法是叠两层贴图交替重置：A 层流一小段就淡出，不可见时归位重来，B 层错开半个周期接上。拉丝确实解决了，但是整片液面一起淡入淡出，盯久了还是能看出规律的明暗起伏。

Sannikov 的做法是在两层的混合权重和相位里加了一层空间噪声。这样这一小块刚准备换层，旁边那块已经换完了，局部照样在周期性重置，整片岩浆看过去就找不到统一的节拍（原片 01:30–02:45）。

他把这份 Shader 直接传上了 Shadertoy。聊到图形编程怎么入门时，他的建议也是找一份能跑的代码，动手改一个参数，看画面哪里跟着变。


左：朴素平流拉丝；中：双层交替重置；右：叠加空间噪声后的混合掩膜（02:27）

只用 2D 贴图做水下厚度和体积阴影

雾气和浑浊的水都有厚度。正经做三维光线步进，显存得存一套三维体数据，沿视线每走一步还得重新算光照，两头开销都不小。

GGG 的做法是把厚度压回一张 2D 贴图里，思路相当于在水面底下平行放了几层看不见的采样面。当视线斜着穿过水面时，深度越深，射线落在下一层平面上的交点沿表面的偏移就越大。

用切线、副切线和法线搭出局部坐标系 TBN，把视线方向转到切线空间，就能算出每一层该去读哪块 UV。把这几层采样叠在一起，水底碎屑就有了远近层次（原片 03:18–06:08）。

他们拿生命球也试过类似的视差效果，只是当时没来得及放进展会试玩版。毛皮渲染用的也是同一套分层思路，不过只在最外层算一遍完整光照，里面几层直接从屏幕已有的着色结果里取色，省下了大量重复计算。


左：平行采样层示意；中：水下碎屑多层视差；右：复用外层光照的毛皮近景

水里的体积阴影也能复用这套几何关系。影子落进烟雾或浑水里，越往深处边缘越糊，如果专门为体积阴影再加一轮步进采样，开销会涨得很快。

常规阴影贴图为了软化影边，本来就会在表面小范围内多次采样深度图，也就是 PCF。Sannikov 保留了原来的循环次数，只用 TBN 算出的射线方向重新排布了这些采样点的位置，让它们不再平铺在表面，而是沿着射线深度一深一浅错开。

采样次数一点没加，影子在浑水里逐渐发虚的效果就出来了（原片 06:42–07:53）。

接触视差和接触贴花

石堆摆在起伏的地面上，或者一张血迹贴花斜着穿过地砖，硬件深度测试只会直接切出哪边更近，留下一条很整齐的硬交线。GGG 用了两个相近的办法，分别处理凹凸地形和平面贴花（原片 08:10–12:25）。

第一个是接触视差（Contact Parallax），专门管视差贴图画出来的石堆凹凸。如果直接改写片元深度来修正遮挡，不仅会破坏 GPU 的 Early-Z 优化，交界处还容易出锯齿。

所以团队不碰深度写入，改按视差层和真实地面之间的深度差做平滑淡出，交线自然就融进地面里了。

第二个是接触贴花（Contact Decals），麻烦比石堆多一层：除了边缘要淡出，花纹本身的位置也不能飘。普通平面贴花斜铺在地上，一部分埋进土里、一部分悬在空中；换传统投影贴花开销又太高；如果只做深度淡出，埋在底下的那半截图案会随着镜头移动乱滑。

团队借了视差遮蔽映射的思路，先沿视线求出与真实地面的交点，再用这个交点去校正贴花的 UV。在 12:11 的棋盘格测试里，贴花网格明明斜插进地面，画面里的方格却稳稳沿着地形铺开，美术摆贴花时也不用逐个去对齐起伏。

三个实用的特效与材质工具

序列帧运动矢量

为了省显存，火焰和烟雾常压成 9 帧或 16 帧的 Flipbook 序列图。直接切会跳帧，简单叠化又有重影。

加上运动矢量后，切换时把上一帧顺着运动方向往前推一点、下一帧往回拉一点，两张对准了再做淡入淡出，16 帧播起来也会顺滑很多。

难点在于两张静态图之间没有唯一的运动场，GGG 写了个离线层级求解器来算：

  1. 把源帧放进红通道、目标帧放进绿通道，完全重合的区域会显示成黄色。
  2. 先在 4×4 的粗网格上对齐大块火苗。
  3. 逐级加密网格，把边缘残留的红绿错位一点点修成黄色（原片 12:35–15:15）。

弯曲法线阴影

普通法线贴图只能改表面朝向，画不出凹凸之间的自阴影。GGG 把烘焙好的 AO 和弯曲法线（Bent Normals）拼成一个可见锥：AO 决定锥体开口有多大，弯曲法线指明锥轴朝哪边。如果没单独烘焙，用普通法线或粗 Mipmap 也能代替。

渲染时只要判断光线是否落在锥体外面，就能用很低的成本补出微表面阴影。

更有意思的是，连游戏里纯 2D 资产拼出来的 UI 也接了这套算法。场景里技能发光时，界面边缘的浮雕也会跟着投下实时阴影（原片 15:42–17:43）。

GPU 粒子

分支逻辑多、关系到玩家掉不掉血的判定照旧留在 CPU，大量重复计算位置和速度的视觉碎屑全挪到了 GPU。同样给 1ms 预算，能跑的粒子数大约差出两个数量级（约 100 倍），GPU 还能直接读深度缓冲，粗略判断碎石砸到地面后的反弹方向。

这套粒子系统和材质共用同一个可视化节点图编辑器。特效美术连好节点，就能做出陨石冲击波掀飞碎屑，或者冰盾粒子随角色移动并在受击时四散的效果（原片 17:52–20:05）。

拍岸浪和 Fields 工具

把拍岸浪的参数锁进安全区间

远海波浪有现成套路，河水靠流向图也能搞定，唯独拍岸浪最难算，因为它的涌上与回退完全跟着海岸线的弯折走。Sannikov 把水面的几何运动和水色光学拆开处理，先管住波形本身（原片 20:18–24:35）。

调一片海滩可能牵扯几百个参数，很多值一旦填出合法范围，整套算法就会出乱子。所以他们把所有参数统一映射到 [0, 1]，防止美术输个 1.3 把波形假设破坏掉。

在调试视图里，海岸线旁被划成一排平行条带，每条带放一层浪，先用取值卡死在 [-1, 1] 之间的正弦波占位。锁死振幅有个很实在的好处：一层浪最多只可能伸进隔壁那条带，所以屏幕上的任意一个像素，片元着色器最多只需要算两层浪。如果参数越界导致第三层浪进来，计算量和叠合关系就会全乱。

等拍岸节奏调顺了，再把正弦波换成不规则噪声纹理，盖上水色、泡沫遮罩和折射畸变，海浪就自然多了。

用 Fields 同步推导法线

两团熔岩或者泥浆融到一起时，表面高度变了，法线也得跟着重新偏转，否则高光会显得很假。Demoscene 圈很常用 Field（场）来保住值和导数的关系，但在商用引擎里直接做成美术节点并不常见（原片 24:58–26:32）。

GGG 的 Field 把标量值和它的空间梯度一起打包成 float3：(f,∂xf,∂yf)(f, \partial_x f, \partial_y f)(f,∂x​f,∂y​f)。两个场 A=(a,∇a)A = (a, \nabla a)A=(a,∇a) 和 B=(b,∇b)B = (b, \nabla b)B=(b,∇b) 做常规运算时，导数跟着同步推导：

  • 加法直接相加：A+B=(a+b,  ∇a+∇b)A + B = (a + b,\; \nabla a + \nabla b)A+B=(a+b,∇a+∇b)
  • 乘法按求导法则展开：A⋅B=(ab,  b∇a+a∇b)A \cdot B = (ab,\; b\nabla a + a\nabla b)A⋅B=(ab,b∇a+a∇b)

美术把两片岩浆拼在一起，输出结果里直接带着新表面的梯度，着色器拿它重建法线就行，不用美术操心数学。德鲁伊的火山技能就是拿这套节点搭出来的。

辐射度探针层级（Radiance Cascades）

早在 2019 年 ExileCon，Sannikov 就展示过一代用的方差屏幕空间 GI。到了二代，他把之前做屏幕空间阴影时的分层思路搬进了间接光里（原片 26:54）：贴近物体的锐利接触阴影用全分辨率算，稍远的地方降到中等分辨率，最远处大片发虚的软影直接用低分辨率算，最后拼成一张图。

换成全局光照，道理是一样的。把辐射度探针想成插在场景里的小相机，专门记录四面八方照过来的光。这里有个经典矛盾：探针排得越密，空间细节越准；每个探针看的方向越多，角度精度越高。以前大家要么多放探针少看方向，要么少放探针多看方向，怎么选都觉得亏。

Sannikov 提出的辐射度探针层级（后来定名为 Radiance Cascades）把这两种需求按距离拆开了：

  • 近场：离受光点很近时，挪动几厘米遮挡关系就会剧烈变化，所以把探针铺得很密，但每个探针只看少数几个方向。
  • 远场：远处光源隔着老远，相邻两个位置看到的光照几乎一样，没必要密铺探针，但需要分清光从哪个精确角度来，所以减少探针数量，把方向数翻倍。

96 条线段怎么拼出 128 条方向路径

为了把算术讲明白，Sannikov 先画了个二维网格原型（原片 31:20–33:54）：

层级 探针网格 单探针方向数 本层实际计算的线段 合并后累计有效路径
第 0 级（近场） 4×4 = 16 4 条短段 16×4 = 64（记为 K） 64
第 1 级（远场） 2×2 = 4（数量 ÷ 4） 8 条长段（方向 × 2） 4×8 = 32（0.5K） 16×8 = 128
第 2 级 数量再 ÷ 4 方向再 × 2 16（0.25K） 256
推广到第 N 层 每层 ÷ 4 每层 × 2 累计 2K(1−2−N)<2K2K(1 - 2^{-N}) < 2K2K(1−2−N)<2K 随层数翻倍

看起来违背直觉的地方在于，第 0 层算了 64 条短线段，第 1 层算了 32 条长线段，加起来明明只算了 96 条，怎么会凑出 128 条路径？

答案是复用。合并第 0 层和第 1 层时，细网格上的 16 个探针各自用自己的近场短段，去接粗网格插值出来的 8 个远场方向，拼出了 16×8 = 128 条完整路径。

每一层往上走，探针数缩成四分之一、方向数翻一倍，所以每层的计算量都在对半砍。哪怕把无穷多层加起来，线段评估总数也不会超过第 0 层的两倍（2K）。

当然这笔账也有代价。因为远段是借相邻粗探针算出来的，两段接在一起时射线会微微弯折，所以叫折线近似（Bent Rays）。只要每层线段长度相对受光距离控制得够短，这点弯折带来的误差肉眼基本看不出。

另外 2K 只是这个二维模型里线段评估次数的理论上限。真放到 GPU 上跑，级联插值、合并、纹理读写和多次 Dispatch 都会占掉一部分帧耗时，不能直接划等号。不过核心账依然划算：往远处扩展光照范围时，不用再把每条射线从头追到尾。

现场问答记录

演讲最后的问答环节聊到了不少具体的工程取舍（原片 39:28）。

有观众关心满屏放技能会不会把新 GI 拖垮。Sannikov 举了个极端例子：画面里一颗火球和一百万颗火球用的是同一套探针网格，只要分辨率和级联设置不变，GI 本身不会因为光源变多而多算一轮，他粗估这部分大约花 1ms。当然，模拟和渲染那一百万颗火球本身的开销得另算（40:42）。

关于为什么不放开水平自由视角，回答很现实：自研引擎围绕固定俯视角做了大量剔除和简化。录宣传片时偶尔把镜头拉近压平，平时藏得好好的穿模和背面缺面就全露馅了（41:28）。

另一位观众问为什么当时没上 TAA。Sannikov 坦言自己看宣传片时也会盯着局部的镜面走样看，但《流放之路》里技能闪灭太快、角色位移太猛，时间性抗锯齿重投影历史帧很容易拖出重影，反而干扰战斗辨识（44:00）。

一二代共用同一套引擎代码，显存差距主要出在资产规格上。贴图边长哪怕只翻一倍（比如 512×512 升到 1024×1024），同压缩格式下显存占用就会直接翻到 4 倍。新的 GI 也会往一代搬，只是当时那次一代补丁底层改得太多，团队决定分批合入（47:00）。

聊到图形程序员最怕遇见的边界情况，他点名了水火叠层和各种奇葩商城外观。角色走进水里或火里，层叠淡出远比普通平面复杂；要是玩家再穿上把整个人变成一团水之类的外观，半透明材质撞上视差很容易打破预设假设，只能专门打补丁（44:25）。

团队内部也有意思的信息差：有特效美术把 Fields 节点叠了好几层做熔岩，也有人平时赶排期，直到展会彩排看见幻灯片才知道引擎里早就有某个现成功能（48:30）。

最后有人请教平时怎么学图形学。GGG 只要不涉及剧透和未公开排期，挺鼓励程序员对外分享技术，Sannikov 自己在 YouTube 频道 @Alexander_Sannikov 上也发过 2D GI 原型。

他觉得物理底子对模拟光和材质很有用，平时玩别的游戏也会带着问题去拆：看到《怪物猎人》的毛皮在屏幕边缘被切掉，就能猜出它走了屏幕空间方案；他甚至专门钻到《艾尔登法环》的老鼠模型底下，就为了看看正常游玩时看不见的建模死角（40:10 · 49:45）。

5. ExileCon 2026 引擎专场：六个人怎么维护两代《流放之路》的渲染与工具

原片：《ExileCon 2026: The Engine of Path of Exile》（ExileCon 2026，约 50 分钟）
讲者：Grinding Gear Games 首席引擎程序员 Alexander Sannikov；文中帧耗时均为讲者现场口径，配图按时间戳截自原片。

在 Kingsmarch 摆下一台地图装置，或者刷图遇到深渊裂口，脚底的石板路会直接凹下去一块，里头能看见岩壁，洞沿还带着投影。那条路本身是平的，深渊更是随机刷在拼接地形上的，美术不可能给全游戏每块地砖都单独做一份带洞版本。

Alexander Sannikov 在 ExileCon 2026 引擎专场就是拿这个问题开场的（现场提问）：不动地面网格，怎么在任意位置给石板开口？

Cutout：靠模板缓冲在地面开洞

按默认深度测试来画，镜头先看见石板，石板底下的深渊模型会被全部挡住。如果干脆关掉深渊的深度测试也不行，那样洞里的东西会盖到走过洞口的角色头上，洞沿和后壁的遮挡关系也会乱掉。

真正需要改的只有洞口这一小块区域的深度。GGG 的 Cutout 分三步处理（原片 02:31–03:21）：

  1. 在洞口摆一块隐形辅助几何体，不写颜色，只往模板缓冲里打标记。
  2. 跑一个独立 pass，把所有打了标记的像素深度统一改写成无穷远。
  3. 照常开启深度测试，绘制深渊的地下结构。


左：默认深度遮挡；中：模板遮罩；右：重设深度后的地下洞壁

这样洞口外侧依然保留石板的深度，洞口内部则重新按远近排序。地下岩壁照常受光、投阴影，地面网格完全不用切，原有的碰撞和寻路数据也没受影响。

这套 Cutout 还能绑在角色脚下跟着移动。演示里的关卡无缝切换也是同一种做法：角色从 Holodeck 走进钢铁、黄铜或岩石城塞时，旧场景逐步消散，新场景直接浮现出来（原片 04:00）。

材质图系统：多图叠加与节点组

一块材质如果既要做 Cutout 又要加视差映射，把两张现成的节点图手动揉成一张最难维护。

《流放之路》的做法是让美术直接往物体上挂多张独立功能图，各用各的参数面板，执行顺序交给编译器按 Stage 排。只要每张图声明好自己在哪个阶段读写哪些属性（比如前一张算完顶点偏移，后一张读取偏移后的位置），编译器就能自动理顺依赖，挂图顺序不影响结果（原片 05:15–05:42）。

节点组最初只是美术提需求，想在图里画个方框写注释。引擎组发现，只要框里的计算有了明确的输入和输出，外层就能把它当成函数反复调用，后来基于这个机制扩展出几个常用工具（原片 07:25 / 12:48）：

  • Field Group：做地裂这类凹凸效果时，美术不用再手推法线，只要在组内输出高度。外层会在相邻坐标多采一次高度求梯度，换算出法线再和原地表法线混合，同一道裂纹搬到任何斜面上都能正确受光。
  • Mesh Deform Group：遇到网格弯曲变形时，组内只负责写顶点位移，外层按变形后的几何自动重算 TBN，高光朝向不会出错，美术也不用碰矩阵。

衰减曲线也改了做法。以前美术调一条曲线，得在图里串一长排 smoothstep 和幂函数节点。直接拖样条曲线倒是方便，但控制点一多，在 Shader 里实时计算又太贵。

引擎干脆在运行时把每条样条烘成 1D 纹理，上千条拼进一张 2D 查找表。Shader 里查曲线只需要一次纹理采样，开销和控制点数量无关，游戏里大部分特效曲线后来都切到了这套方案（原片 08:10–09:26）。

大面积铺石砖或水面时，最容易露馅的就是贴图重复平铺。Interpolation Group 会把平面切成六边形单元，用单元编号作为输入去调用美术写的节点组，外层自动处理好相邻单元边界的平滑过渡。

美术只要按编号加一层随机 UV 偏移就能打散重复感。如果再接上流向图，关掉调试色块就是连贯的水流，熔岩和火焰也能照搬这套做法（原片 10:46–11:50）。

GPU 粒子、斜投影阴影盒与看台人群

粒子行为图和像素、顶点着色器共用同一套材质图系统，重力、质量、空气粘滞阻力都可以直接在图里调。

演示里碎石聚成墙、怪物 Bodek 登场砸地，就是多张图配合的效果：地裂法线走 Field Group，碎石走物理粒子图，绕着怪物轮廓飞的蝴蝶则由网格发射器生成。

砸地那一刻，CPU 只发一条“这里砸地了”的事件，碎石的飞散和弹跳全在 GPU 上算。按 Sannikov 的估算，这种规模放 CPU 上得吃掉几十毫秒，放到 GPU 上远低于 1 ms（原片 13:35–15:05）。

迷雾终局 Boss 的碎屏效果用了 Snapshot Capture：裂开前把当前帧缓冲拷进临时纹理，每块飞出的碎片直接采样这张快照，画面就会像碎玻璃一样崩开（原片 15:40）。

阴影这边也利用了固定俯视角的特点。玩法区域基本摊在一个平面上，如果按常规斜着套一个正交阴影盒，大量阴影贴图纹素会浪费在半空和地下。

团队改成了 Box Light，允许投影矩阵非正交，投出一个斜平行六面体。光线斜射到地面时刚好紧贴可见矩形，不加分辨率也不涨显存，地面阴影清晰度就提上来了（原片 17:36）。

演讲中间还穿插了两个复用现有管线的例子（原片 18:52–20:20）：

  • 章节世界地图看着像手绘插画，底层其实是游戏常规的 3D 地形系统，内部甚至有张能让角色直接跑上去的测试图。
  • 看台上坐满的几百名观众全部走 GPU Instancing 绘制，CPU 每帧只更新三五个父对象，其余观众全在 GPU 里复用数据。

左图直接把 Substance Painter 导出的高度图贴在鼓起网格上放到地面，交界处是一圈很明显的圆硬边。中图开了 Parallax Contact Fade，鹅卵石立体了，边缘也自然嵌进了砖缝。

但全游戏到处铺开之后，视差映射的开销肉眼可见地涨了上来。团队试着砍掉视差，只留 Height Contact Fade，也就是右图的效果：斜看虽然少了石子随镜头移动的凹凸感，可和地砖相接的边缘过渡几乎没差。

大多数场景本来要的也就是这个贴地过渡，没必要硬上视差。真碰到需要改外轮廓的地方，再另画一遍 Outer Parallax 补边就够了。

调试三件套与 Linux 支持

因为现场时间紧，Sannikov 跳了几页性能分析，重点讲了日常排查最常用的三个调试工具（原片 25:36–26:54）：

  • Multilayer Picking：光标底下叠着七八层透明粒子和网格、掉帧不知该查谁时，它会把射线穿过的所有资产列成清单，点开就能看来源、Draw Call 和管线统计，顺带也能查树木穿模。
  • Tracy：遇到一闪而过的偶发卡顿，里面录着 CPU 各线程的完整调度时间线，直接翻回出事那一帧就能抓任务次序和多线程竞态。
  • Traps：以前想只在某个对象的特定阶段停住，得改代码插条件断点、重新编译再复现。现在引擎关键阶段预埋了默认休眠的陷阱开关，游戏里点中对象勾一下阶段，下一帧跑到那儿直接进调试器。


左：Multilayer Picking；中：Tracy 多线程时间线；右：对象断点 Traps

讲到 Linux 支持时他明确表态：不限于 SteamOS，普通能跑 Steam 的 Linux 发行版都能玩，他自己在家就用 Linux。他还顺嘴吐槽了一句，至少那阵子避开了 Windows 24H2 的死机，以及部分显卡驱动导致的 Device Removed（原片 27:20）。

Radiance Cascades 的三条路线与太阳物理论文

火球飞过暗房，墙面必须立刻亮起来，火球灭了也要马上暗下去。市面上很多实时 GI 靠时间累积和降噪摊成本，哪怕每帧只花 5 ms，收敛也得攒上百帧。放在瞬发技能满屏飞的《流放之路》里，墙上的光会拖在火球后头。

Sannikov 在 ExileCon 2023 公开的 Radiance Cascades 就是冲着单帧收敛去的。近处空间探针密、方向分辨率低，专门抓接触阴影；远处空间探针稀、方向分辨率高，专门区分远光来源，最后把高层级联往低层合并（原片 31:02–31:46）。


左上：近场 Cascade 0；右上：远场 Cascade 2；左下：级联合并；右下：叠回材质与 AO

到了 2026 年，这套思路已经分化出三条并行演进的路线：

方案 落地状态 单帧耗时 / 收敛（现场口径） 核心优缺点
屏幕空间 Radiance Cascades 《流放之路 2》已投产 约 1–2 ms / 单帧收敛 1 颗火球与 100 颗火球算同一组级联（不含画火球本身）；屏幕外光源算不到
世界空间 Sparse Radiance Cascades（硬件光追） 接近投产原型 约 5 ms / 收敛约 5–10 ms（关重投影约 8 ms） 屏幕外光源也能照进屋；超预算，依赖硬件光追且要实时维护动态粒子与骨骼网格的 BVH
世界空间无光追锥追踪 实验原型 尚未达到投产指标 直接拿表面探针当几何做锥追踪，砍掉三角形 BVH 和光追依赖；漫反射接近左图，精度仍有差距

屏幕外光源算不到的问题，靠 Sparse Radiance Cascades 来解。它只在几何表面撒探针，近密远疏，保证每个探针投影到屏幕上的像素面积大致相等，方便卡死显存和单块探针数量上限（原片 34:16）。

在世界空间实机演示里，开启时间重投影时单帧约 5 ms、收敛约 5–10 ms。现场关掉时间重投影并排对比，画质依然很接近，收敛约 8 ms，屏幕外的光源也能照亮室内。

不过 5 ms 已经超预算了，而且正式游戏里粒子和蒙皮骨骼每帧都在动，给硬件光追实时维护加速结构 BVH 的开销绕不开。

台上他还放了一段自己计时 40 分钟写完的镜面反射 Demo，调侃行业里满街积水的展示套路叫“湿沥青综合征”。镜面反射方向明确，光追本来就好画，真正难的是要顾及四面八方的漫反射（原片 36:00）。

既然探针已经沿几何表面铺开了，干脆拿探针直接当几何体来做锥追踪（Cone Tracing）。不靠硬件光追，右图的漫反射已经和左图非常接近，只剩细节精度差距（原片 38:45–38:55）。


左：硬件光追驱动；右：直接追踪表面探针的锥追踪原型

现场有人问这套方案什么时候进游戏，Sannikov 说世界空间原型已经接近投产，合进去前的最后一道槛就是彻底去掉对硬件光追的依赖（投产进度说明）。

比较意外的是 Radiance Cascades 在游戏圈外也有不小的反响（原片 39:20–42:40）。2023 年公开之后，几千人在图形学社区里一起往前推，衍生出了面向 2D 的 Holographic Radiance Cascades，以及算体积雾烟的 Split Radiance Cascades。

后来甚至有天体物理学家找上门来。格拉斯哥大学的 Christopher Osborne 和 Sannikov 合写了一篇非局部热动平衡辐射输运论文（arXiv:2408.14425），把级联复用放进 DexRT 求解器里算太阳日珥的辐射场，因为恒星大气辐射和游戏算光底层是同一套数学方程。

社区里还冒出了热传导、寻路、黑洞引力透镜的 Shadertoy，以及 Untitled Pixel Simulator、Core Keeper 开发商新作等 Steam 游戏。大家还调侃，写 Radiance Cascades 写挂了特别容易在屏幕上画出分形。

当然这套方案还没彻底收尾。Sannikov 最后点出两个没啃完的难题：单像素极小光源容易采偏，工程实现的算力也还没压到理论最优。

现场问答：六个人怎么守住两代引擎

被问到只有六个人的引擎组怎么撑起整个项目时，Sannikov 的原则很克制：代码写进去以后就得有人养，所以尽量少写新代码，把精力花在现有模块的性能和调试工具上（原片 44:20–49:30）。他顺口提了一句“整个引擎大概只有 250 KB”，不过没展开这具体指哪一块源码或编译产物。

两代游戏共用一套底层代码，二代改底层会直接编进一代，给一代加赛季功能也得兼顾二代。PC 和主机共用绝大部分上层逻辑，只拆最底层的平台后端，所以不用养庞大的移植团队。Mac 原生版还在做，现场没给日期。

至于为什么暂不接新版 FSR，原因是新版转向闭源，还强制要求管线提供运动矢量，改造量不小。他对现有的 DLSS 画质很满意，主机也有各自升频方案，当下没接入的必要。

有观众担心几千万多边形时 GI 顶不顶得住，三条路线各自有不同的开销增长方式（锥追踪复杂度目标）：

  • 屏幕空间版只读缓冲，根本不挨个碰多边形。
  • 光追版靠加速结构，复杂度呈亚线性增长。
  • 无光追体素锥追踪的目标是把开销绑定到体素尺寸 N，压到 O(log N)，跟场景多边形数彻底解耦。

聊到动态模糊，他本人就不喜欢让整屏糊成一片的运动模糊和某些抗锯齿，战斗得看清动作，所以团队拒绝全屏运动模糊，刀光拖尾交给美术局部画。

最后被问到程序化地形怎么影响引擎设计，答案又回到了开场那条石板路：固定地图可以提前把洞挖好，正因为深渊会随机刷在任意一块砖上，Cutout 才成了刚需。

6. ExileCon 2019 特效演示：从零搭出一个 1 秒预警爆炸

原片：ExileCon 2019 特效现场制作与问答
讲者：Grinding Gear Games 特效美术 Ivan Leong，首席动画师 Sam 主持问答；演示为 3.9“异界征服者”上线前的教学原型（与正式版 Boss 特效有区别），配图截自原片。

设计组递过来的需求单只有几句话：3.9 异界征服者里的圣战者，视觉关键词是闪电、魔力和神圣，施法后在地面来一次带 1 秒蓄力预警的圆形范围爆炸。

看着简单，但真放到制作台上，这一秒里要装进好几层互相配合的信号：地上符文先亮，四周光柱慢慢升起来，中心徽记在最后一刻骤亮，紧接着才是爆炸、气浪和火星落地。

在 GGG 干了六年特效的 Ivan Leong，在 ExileCon 2019 现场直接打开 Photoshop、Maya 和自研的 Asset Viewer，当着台下的面把这套技能从黑底圆圈一路搭到完整引爆。中间虽然跳过了琐碎精修，不过平时复制节点图、去老库翻贴图的工作习惯都留了下来。

先画黑白灰度图：游戏特效主要靠贴图

特效组管的事情很杂，从剑刃挥出的光迹到场景里的瀑布全归他们。Ivan 专门把战斗预警（telegraphing）单独拎出来讲：挥砍、猛击、范围炸裂、传送、投射物，只要带预警，都得跟设计师和动画师严密卡住命中点，有的还要配合特定场地机制。

除了战斗技能，技能皮肤、武器、护甲、传送门这类商城外观吃掉大量工时，环境里的熔岩流、毒气风场和任务遭遇战也得接（原片 00:16）。

Ivan 以前做影视和广告，转进游戏后最先适应的一点就是每一帧都得实时算完（原片 17:00）。影视里动辄上百万粒子的物理模拟在游戏里算不动，靠堆粒子填体积也不划算，所以游戏特效大多走贴图驱动：同一张图贴到不同模型上、换个显隐节奏，看着就是完全不同的技能。

圣战者的地面预警就是典型做法。Ivan 在 Photoshop 里画圆、划几何分区、描符文，把整套地面拆成四层纹理（原片 03:31–06:01）。

特效行业有个很实用的习惯：贴图尽量存成黑白灰度图，只管明暗，颜色留到引擎里用材质参数调（原片 07:46）。这样同一张符文改个颜色，就能借给火系、冰系技能接着用。

贴图画完后切进 Maya，给四层图建平面网格、做好 1 秒 Alpha 显隐动画，再摆好待会儿挂粒子用的骨骼关节，一并导出进 Asset Viewer。

地面四层分工

在 Asset Viewer 里调出圣战者的施法动作 spell_cast_range_03，地面一开始只有光秃秃的 1 秒渐显。Ivan 一层层取消隐藏，给四张贴图派了明确分工（原片 05:31–12:51）：

层次 视觉作用 混合模式与光照 配色与关键调参
1. 地面焦痕 压暗符文底下地表、托出亮色 正片叠底 + 关光照 不受场景光干扰，同时透出原有地表纹理
2. 主符文圈 勾勒攻击范围与魔力、闪电基调 Alpha Test + 关光照 避免细笔画被半透明糊掉，实例节点乘 RGB 调蓝并拉亮度倍增
3. 中心神圣徽记 临近 1 秒引爆前骤亮，提示危险 Additive + 关光照 直接复制主符文节点，改略暖白色并压低过刺眼的倍增系数
4. 最外围旋转环 补齐边缘动态，但不抢视觉焦点 Additive + 关光照 UV 平铺设 2 拆对称两段，约 1.5 速度滚动，低饱和偏粉白

调色走的是实例化材质节点图库，思路跟 Unity、Unreal 的材质实例差不多。Ivan 把动画定格在蓄力中段，拿贴图 Albedo 乘 RGB 向量边看边调蓝，色相准了再推亮度倍增器。

轮到中心徽记时，他直接点了 Copy All 把主符文的两个颜色节点整套拷过来。刚粘上去的徽记又蓝又刺眼，他在实例里拧成代表神圣的暖白色，再把倍增压温和。

外圈旋转环把 UV 平铺设成 2，滚动速度给到约 1.5。颜色刻意压成低饱和偏粉白，免得喧宾夺主抢走玩家盯中心的注意力。

点发射器也要绑两根骨骼

接下来往时间轴上挂粒子特效，负责蓄力光柱和引爆火花。整条资产时间轴总长约 2.63s，他在 0s 挂蓄力模板 build_up_point，在 1s 挂爆炸模板 boom（原片 13:46–16:02）。

GGG 引擎有个挺特别的设计：用 Maya 导出的骨骼关节来定粒子发射器形状，方便特效跟着角色动画一起移动。哪怕只需要一个发射点，也要在骨骼组里选两根关节：

  • 点、线、球体、圆柱需要 2 个关节，靠两点定位置和尺度（圆柱的第二点用来定半径和高度）。
  • 圆环和盒体需要 3 个关节，盒体还要沿对角线跨过去摆，Ivan 自己都吐槽这种摆法没前面几种直观。

选好两个关节编成 point 组存进动画对象文件，后面设计师就拿这个文件去绑游戏事件。

至于粒子贴图，Ivan 很少每次从头画，习惯先去老库里翻，他把这叫逛贴图超市。旧贴图换个材质或拉伸方式经常直接能用（原片 17:47）。

蓄力光柱：把圆柱模型的硬边藏起来

0s 蓄力启动，一圈光沿符文往上升。默认的方形面片不合用，Ivan 换成网格粒子，在发射点放一个朝向固定的静态圆柱模型，让纹理沿着表面往上滚，发射模式设成单次爆发，寿命正好 1s（原片 18:32–22:15）。

套上默认材质时，圆柱看着就是个呆板的直筒，他接连调了三步：

  1. 切 Additive，在粒子材质里再单勾一次关闭光照，把模型微微下沉贴合地面。
  2. 挂上 Scale/Move UV 节点，让贴图沿圆柱表面往上滚。
  3. 用底部生命周期曲线控节奏：先慢慢往上爬，卡着 1.0s 冲到顶峰，随即断崖掉回零，刚好接住爆炸。

不过还有个破绽：套完蓝光，圆柱左右两条笔直的侧边依然清晰可见，一眼能看出里头放了个几何体。加上 Fresnel Fade 节点后，越靠近圆柱边缘表面越透明，原本生硬的轮廓线就会淡掉，看起来像一团往上升的蓝光。

1.0s 引爆：四层错开寿命

时间轴走到 1.0s，Ivan 把 boom 模板挂回同一个骨骼组。一次有劲儿的爆炸，关键是同时触发、错开消失：闪光先收，气浪接着散，火星最后坠地（原片 23:02–28:31）。原型一共叠了四层：

层次 寿命设置 做法与视觉职责
1. 中心耀斑 0.2s（缩放按 0.15s 微调） 方形 Sprite 单次爆发，Additive 关光照，复用颜色节点去平铺，调成近白亮暖黄负责瞬时炸亮
2. 扩散冲击波 约 0.3s 复制发射器换扭曲贴图（红绿通道指明像素偏移）配 Shimmer 折射预设；调低初始过绿的扭曲度并放大面片，拉出一圈气浪
3. 飞溅火花 0.8 ± 0.05s 拉高发射数与初速度、缩小颗粒并加寿命抖动；Additive 蓝光配速度朝向锁定拉长光迹，再加重力坠地
4. 球体柔光 随爆裂闪现 不用贴图，空材质直连纯色 RGB 套球体网格粒子，加 Fresnel Fade 消边降透明，补一团立体柔光

火花这层折腾的细节最多。0.5s 显得太短促，他延长到 0.8s 再加 ±0.05s 浮动，免得所有火星齐刷刷同时灭掉。材质先试过 Alpha Test，随后改回 Additive 自发光蓝色（原片 28:48–32:35）。

为了做出火星划破空气的锐利拖线，他拉长粒子并勾上 Velocity Lock，让拉伸贴紧飞行方向，再配一条随时间减弱拉伸的曲线加上重力（原片 31:16）。

最后那层球体补光非常省资源：空材质连个纯色 RGB 加 Fresnel Fade，不占贴图显存，就给扁平的 Sprite 补出了看不出球形的立体柔光（原片 33:31–35:25）。

做到这步，Asset Viewer 里已经能从头播到尾了。平时接下来会把动画对象交回设计师接游戏逻辑、进客户端实战，真打起来如果预警看不清，或者炸点跟判定错帧，特效组再领回去修（原片 36:01）。

现场问答

演示结束后是问答环节，由首席动画师 Sam 主持（原片 36:46）。

做一个特效到底要几天

Ivan 是 GGG 招的第 2 名特效美术，当年入职时全公司才二三十个人，挤在两间小办公室里。后来赛季越滚越大，他除了亲手做资产，还要排工期、审稿、沉淀流程带新人。

平时沟通最勤的是设计师，动作和场景对接动画组、关卡组。遇到拿不准引擎能不能撑住的需求，就直接找 Erik Olofsson 和 Jonathan Rogers 拍板（原片 37:16–41:17）。

新人总爱打听做一个特效平均要几天，好心里有底。Ivan 给不出标准答案，因为很多时候想清楚怎么做，比动手做花的时间还长。

他最得意的作品是第六章 Boss 惊海之王的海啸水墙：设计师只说要有东西从四周往中心压，没定非得是水。Ivan 想到小时候听的摩西分海和一部 CGI 电影，才定下浪墙方案。单是琢磨怎么让玩家看懂场地在缩就耗了大半周，路子一旦想透，真正做出来最多花了三天（原片 42:16–43:45 / 47:16）。

测得好好的技能，进终局还是满屏光污染

台下票选最高的问题一点没客气：满屏光污染怎么治？旁边的 Sam 趁机吐槽，说特效早把他的角色动画盖得连影都没了（原片 44:15–46:30）。

Ivan 讲得很坦白：设计师既想要高可读性，又希望画面够炸、拿出去能跟同类大作拼卖相。单放一次看着刚好，可组队叠人或者技能本身能高频连发，同片特效叠十几层就彻底糊了。

要是设计师提前打招呼说这技能能狂按，特效组做单次效果时会主动减层、调淡。可真到了玩家手里，终局构筑把攻速、施法速度、光环和触发机制全堆上去，再撞进怪海，画面跟内部试玩完全两码事，QA 人手有限，不可能穷举所有终局组合。

正常流程是美术做视觉版、设计师试玩、QA 压测，进实机后再按帧率做减法，Sam 提到这就是日常的 cutbacks（原片 51:15–52:31）。

Ivan 也坦承美术对帧耗数字不敏感，掉帧了得靠引擎组指明砍哪块。上线后真有流派叠出严重光污染，他们也会回头把旧特效削薄、调淡。

赛季死线撞上工具开发

问答后面聊到了工具链，主要是特效组能不能催引擎组加功能，以及工具开发和赛季内容抢人手怎么排（原片 48:00–53:32）。

特效组和引擎组坐在同一片开放工位，想要什么直接走过去聊。有时反过来是 Jonathan 提了个新点子，大家试完才发现缺引擎功能。

Sam 很看重省掉日常机械操作，每次花 30 秒到 1 分钟的事，写脚本压成 1 秒，一年能省下大把时间。Ivan 自己就找隔壁程序员学过用 Python 给 Maya 写自动化脚本。

但一撞上赛季死线，铁律就一条，content always comes first，内容永远排第一。新需求确实会推着引擎组补工具，可如果新工具赶不上这季上线，美术就得先拿手头的贴图、材质和动画把效果做出来。

二、战斗、技能与物品机制

7. 挥出一记两秒重锤：ExileCon 2023 角色技能与动作拆解

场次：ExileCon 2023 角色技能专场｜讲者：Rory Rackham（技能负责人）、Ed Tate（动画师）、Jonathan Rogers（总监）｜原片：YouTube 00:15
说明：此时《流放之路 2》已确定独立成作。对比 2019 年那套围绕主孔与旧装备兼容的插槽方案，这一场重点讲的是动作手感、多技能分工和武器双专精。

放到《流放之路》一代的节奏里，让你花整整两秒挥一记重锤，几乎没人肯用。刚按下去半秒，怪物往旁边挪了一步，这一锤不光砸空，原地罚站还容易暴毙。

ExileCon 2023 的角色技能专场就围着这记两秒重锤展开：技能负责人 Rory Rackham 讲为什么值得花两秒打这一下，动画师 Ed Tate 讲怎么让人一眼看出发力过程，总监 Jonathan Rogers 盯着这两秒里玩家还能做什么。

2019 年他们主要在解决怎么让角色多带几组满连技能，到了 2023 年，问题变成了手里明明有好几招，实战里什么情况下才值得换招。

边跑边挥出的第一刀

一代动作僵硬，很大一部分是老底子欠的债。七个职业用的骨架各不相同，骨骼命名也不统一，有些动画甚至是硬调关节拗出来的。想改一个施法姿势，最多得给七个职业、每种武器组合全改一遍（原片 01:19）。

因为改动画成本太高，早期不少技能只能共用动作，从起手到收招全得站桩。为了少罚站，最省事的办法就是把整段动画暴力加速。

二代换了统一的新骨架后，Ed 做近战的第一步是把音效和特效全关掉，只盯着最普通的一记挥剑看。没有粒子和音效衬托，这一刀本身也得显得有分量。等动作站住了，再照着挥砍方向和怪物血液颜色去补命中特效。

手感变化最直观的地方，是跑动中劈出去的第一刀。一代角色必须先跑到怪跟前、停稳脚步、再抬手挥刀，怪物往往就在你停步那一刻先手反击。

二代的角色离目标还差一步就能起手，借着最后一步跨出去，刀正好落下来（原片 06:03–07:24）。哪怕面板攻速一点没变，这一刀也更容易抢在怪物抬手前命中。

劈砍得从脚下借力，如果锁死髋部只动上半身，跑着接挥刀会非常别扭。团队按前摇长短配了好几种下半身迈步动画，短前摇还得看角色当下正迈左脚还是右脚，免得一挥刀双脚突然顺拐换位。

至于迈不迈步，直接看起手距离，贴脸了就原地砍。副手拿盾、剑还是权杖，动作姿态也会跟着调。

跨出去这一步能不能挤开怪，由一套内部叫 pushy mode 的推挤规则管着。具体看双方体型和动作，大怪能推开一群小怪，玩家变身巨熊时也能直接顶开杂兵，不至于刚蹭到第一只僵尸就被卡死。

动作衔接、翻滚取消与法力结算

想让连招流畅，没必要硬把每一下都剪短，关键是省掉多余的归位动作。连续挥剑时，角色不用每砍完一刀都回到待机站姿。Ed 从挥剑轨迹里挑出几组不同动作都会经过的中间姿势，让上一招直接在那里接进下一招，实在对不上才用一小段混合动画过渡。

为了扛住不同攻速，同一招通常备了四个长短版本，攻速快到肉眼看不清的细碎动作，在短版里直接拿掉（原片 13:45–16:34）。

刀光亮起、撞击声响起、武器判定命中的时机，全都对着动画时间轴逐帧对齐。画面里刀挨到怪的那一帧，伤害就正好跳出来。

现场有人问同一件武器换到武僧手里，动作会不会变。Ed 答得很实在：技术上可以全做，但预算有限，专属动作优先给最常用这把武器的职业。其他职业照样能拿，走通用动作，有些会微调肩部姿态留出辨识度。

如果蓄力到一半怪挪位置了，多数攻击允许在前摇阶段微调朝向，前摇越长，能改方向的窗口也越长。动作打到衔接窗口时，想接下一招或者直接走开都行。

实在躲不开，翻滚可以立刻打断当前动作（原片 11:15–11:35）。翻滚起手那段能避开攻击和许多投射物，但砸地类范围技还是得老实滚出圈。

翻滚中途可以改方向，不过滚出去就得把整段动作做完才能再出手。因为开头快、收尾慢，连续翻滚不会比跑步更快。

如果重击按到一半被怪打断，或者自己翻滚取消了，法力会从起手到技能生效之间逐步扣除：已经花掉的不退，还没扣完的也不用再付。

光多给几个六连，玩家还是只会按一招

一代只有一组六连，大家只能把主攻技能往全能方向捏，清图、打 Boss、控蓝耗全指望它。可就算白送第二组六连，问题还是在，因为装备词缀和天赋树往往只养第一招，第二招吃不到加成，多出来的孔还不如全配常驻增伤（原片 19:45–20:49）。

Rory 很明确地排除了两种偷懒办法：不靠长冷却逼着玩家轮流按，也不做成先拿刮痧技能攒资源、再照着 1、1、2、3、4 背公式循环。

换招的理由得看场上的实时局势。比如附近刚好有只残血怪能处决，或者 Boss 刚挥完一套大招留出空档，够你多蓄半秒，这时候换招才合理。

要让备选技能的强度跟得上主攻，2023 年展示版把宝石成长又重做了一遍，和 2019 年比相差很大：

环节 2019 年方案 2023 年展示版方案
技能位数量 依赖装备底材主孔（常规 9 个） 1 级起角色自带 9 个技能位
宝石加孔方式 靠随机掉落高孔同名宝石并转移经验，或工匠石重掷 默认 2 辅助孔，剧情按阶段掉 2→3、3→4 的阶梯升级通货，在原宝石上逐步加孔
辅助孔改色 幻色石整排重洗 允许指定单个孔改色，终局仍保留腐化赌上限

阶梯式加孔的好处很直接：前期掉的都是 2 升 3 通货，你没法把它们全砸在一颗主攻宝石上，手头几颗常用技能自然跟着一起涨孔（原片 23:16–25:45）。

改色也少了心理负担。Rory 举了个常见例子：刚捡到一颗想试的蓝色辅助，包里就剩一颗幻色石。按老规则一点下去整排重掷，没洗出蓝孔不说，原来插着好好的辅助都装不回去。允许单孔改色后，试新招就不用提心吊胆了。

辅助宝石则用来拉出技能分工。冲进怪堆的猛击容易被打断，配抗打断辅助最合适；Sunder 可以站远一点砸，配周期性爆发更划算。像 Fist of War 这种辅助的冷却跨技能共享，每招装一颗也没法轮流触发。

武器底材本身也带倾向，比如锤擅长破甲，别的武器靠辅助也能破，只是效率低一截。

这里有个容易搞混的规则：技能绑在武器上，和职业无关。任何职业扛上长杖，照样能使需要长杖动作的招式。挑武器的主要是攻击技能，大多数法术不挑底材，少数像虚空匕首这种施法动作里真用到匕首的才是例外（原片 46:02–46:17）。

双专精、精魂与控制递增

就算技能孔都够用，两招吃的天赋路线不一样还是白搭。双专精把一部分天赋点拆给两套武器各自独享，保留技能也能分武器组单独配（原片 27:33–29:17）。比如一套走 Spark 清群配感电时施放，另一套切高爆 Arc 打单体。

技能事先绑好武器组，按技能键角色会自动切过去。不过拔武器还是会花点时间，团队打算做切换速度词缀，也考虑过让轻武器比重武器切得快。

保留技能还能和形态绑定，比如把极地装甲绑在熊形态上，变熊自动开启，切回另一套武器照常开别的保留。这省的是切完再补按一次的琐碎操作，代价也很实在：两套都想强，得准备两套像样的武器，实战里也得给换手留空档。

常驻效果和蓝条也彻底分家了。新资源精魂（Spirit）专门拿来养光环和永久召唤物，魔力留给主动施法，临时召唤物照旧耗蓝（原片 30:00）。多带一只永久召唤物，光环能分的精魂就少一块。

切武器不会把整队召唤物清零重招，给它们开的光环可以随组切换。但如果你的精魂有一截是副手权杖给的，切走权杖，那部分精魂撑着的东西也就留不住。另外，角色死了也不用再挨个重开光环了。

慢招想打出来，还得靠控制给窗口。冻结、定身或重晕控住敌人，平时来不及蓄的慢招就有了落点。轻微踉跄和长时间重晕分开算，物理近战尤其擅长打重晕。

为了防六人小队把 Boss 无限控到死，同一种控制反复叠，触发门槛会越来越高。这套保护对玩家也生效：刚解冻没那么容易被怪群接着连晕，就算吃满重晕，也不会像 Boss 那样一躺就是八秒。

长杖、重锤和几段改过的动作

长杖的落雷没暴击球时是带位移的范围技，攒够球再放就是高伤收尾，球靠终结掌处决残血敌人来攒（原片 34:18–36:45）。场上哪只怪残了、能不能摸过去补一掌，直接决定下一招怎么接。

终结掌按徒手攻击结算，拿着长杖也能拍是个特例。换别的情况必须空着双手，左手拎锤右手拍掌是不行的。

Ed 做终结掌动画时，特意在命中的瞬间把长杖往旁边偏开，免得挡住掌心。武僧还有一对意外搭出来的连招：Wave of Frost 往后翻，Whirling Assault 正好往前穿。两招本来是分开设计的，连着按却刚好打出后撤避险再穿回怪堆的节奏。

重锤的 Sunder 就是开头那记两秒重击。Ed 是倒着做这段动画的：先定好跃起砸地的最后一帧，再往前推起锤和蓄力，好让这两秒里每一帧都能看出角色在憋劲。锤头砸地后趁势弹起，也方便接下一招（原片 37:46–38:25）。

另一招锤技第一击带额外晕眩，正好给第二记重砸腾时间，收招还能往前多跨一步。慢招有慢招的用处，攻速也没贬值，快那么半拍抢在怪物出手前砸中它，往往就能少吃一下硬伤害。

开发过程里不少弃稿和半成品，改一改反倒救活了动作（原片 39:45–41:00）：

  • 第一版 Whirling Assault 位移太短，Ed 重做前拿双手剑试播了一眼，发现拿去当双手剑技反倒很合适。
  • 游侠后撤原本带个幅度过大的后空翻，删掉之后利索很多。
  • 连续刺击在俯视角下光看两条胳膊根本分不清刺高刺低，动画师让整个躯干跟着一起摆。

当时也有还没定下来的部分，比如瓦尔技能怎么进新版宝石制作体系，现场还留着问号。

问答里最能看出团队在抠手感的细节，其实是按技能定选目标规则。用终结掌时，哪怕鼠标指着另一只怪，角色也会优先扑向旁边可处决的目标，因为你按这招八成就是奔着拿球去的。

可换成讲究落点的重锤砸击，系统自作主张帮你换目标，反倒会把整发重击带偏。所以就算游戏提供了 总是原地攻击 的开关，Rory 还是打算按技能分别定规则，区分哪些招该迈步追怪、哪些招该钉在原地砸准。

8. 让地上的稀有装重新值钱：ExileCon 2023 物品与通货重做

场次：ExileCon 2023《流放之路 2》物品设计与机制专场｜讲者：Dane Brennand（3D 美术）、Hrishikesh Sidhartha / Hrishi（物品设计师）｜原片：YouTube 00:09
说明：本文梳理的是 2023 年《流放之路 2》确定独立成作后的物品图标、武器分工、词缀池拆分与通货重做方案。

玩过《流放之路》一代做装的人，都遇过一个挺别扭的现状：地上掉两顶同底材、同物等的稀有头盔，一顶已经出了三条好词缀，另一顶全是废词缀。可只要你下一步打算点混沌石，这两顶头盔立马就没区别了，因为混沌石按下去直接全盘重洗。

玩家做装时费尽心思挑词缀，掉在地上的词缀却根本不值钱。在 ExileCon 2023 这场分享里，3D 美术 Dane Brennand 和物品设计师 Hrishikesh Sidhartha（Hrishi）从图标辨识度、武器分工、词缀池拆分到通货和暗金设计，一整套改动都冲着同一个目标去：看一眼地上掉的装备，心里就有数，也真愿意捡起来点两下。

不用悬停，光看图标认底材

Dane 虽然是做 3D 模型的，却特别上心背包里那张 2D 小图标。聊到初代《暗黑破坏神》的屠夫切肉刀，大家脑子里浮现的往往是它躺在背包格子里的剪影，真拎在角色手里模型反倒看不真切（原片 01:02）。

一代的物品图标是十来年陆续补的，画风五花八门：有摆好角度渲染的 3D 图，有手绘卡通图，甚至有一面盾长得像实拍照片。老玩家靠肌肉记忆认得出来，新人对着一堆风格打架的图标根本摸不着规律。

二代索性全走先建 3D 模型再渲染的流程，连药瓶上做装饰的小果实都有独立模型。想换把剑的朝向，转一下模型重新渲染就行，不用重画，只是姿势和灯光还是得美术手动调。

盾牌最能体现这套视觉规矩：同是圆盾，纯属性盾和混合属性盾分别朝向左右两边，Buckler 和 Targe 这类名字也一一对应固定属性类别，看熟之后不用每件都悬停鼠标核对底材（原片 04:05–04:31）。单手斧和双手斧轮廓太像，团队也试过拿朝向区分，不过 Dane 说要是摆出来不好看，以后还可能改回去。

六类护甲沿着敏捷、敏智、智慧、力智、力量、力敏排成一圈再接回敏捷。相邻两类造型可以靠得很近，比如都带兜帽，只是一种兜帽底下还罩着铁盔。从力量往敏捷过渡时，厚板甲臂甲也会一路收窄成轻便皮护腕。

底材名字同样反过来管着造型。现实里的连指板甲手套分量不轻，把 mittens 扣在轻巧的敏智手套上就显得别扭。每类护甲有了明确系列名，美术组内部一提名字，就知道该画多厚实。

暗金辨识度与地区风味

同一件护甲，模型一毫米不动，光换布光就能拍出暗金的味道。Dane 演示用的那件护甲当时连词缀功能都没定：拍普通底材时用冷暖光把外形轮廓照清楚，改拍暗金时压暗四周、给灯光偏色、只聚光照亮关键一处，画面质感一下就拉开了（原片 12:45–12:50）。

但暗金不能光顾着酷，把底材类别藏没了。要是图标画成一把大弯刀，底材却是直剑，玩家一眼就猜错类型。团队当时的目标是让每种底材既有专属图标，也有对应的暗金装。

一代的经典暗金也有不少在回归名单里，Hrishi 现场点了猎首和薛朗的护身长袍的名：留的是大家认得的核心机制，数值和词缀还得按二代规则重新调。

装备长相也跟着战役地区走。演示里第二幕商人摆的是马拉克斯风格装备，第三幕换成瓦尔风格（原片 13:30）。美术组给一个文明定纹样时，会先想他们拿什么符号记乐谱、刻在石雕上长什么样，再把同一套符号搬到武器和护甲上。当地产仙人掌木，握柄的木纹和色泽也就有了着落。

有时候流程还会倒过来，美术先给设计出题。演示里有一根做成握着铃铛的手的法杖，美术画完交稿时自己都不知道它该干嘛，做成法术回响、伤害反弹还是别的机制，全交给设计组去接。

每类武器得有自己的看家招式

一代里虽然剑偏命中、锤偏眩晕，但只要绝大多数攻击技能换把武器照样放得出来，玩家挑装备到头来还是只盯面板秒伤。二代改成了武器本身决定能放什么招：各职业照旧随便拿武器，限制的是哪种武器能做哪个动作（原片 21:30–25:46）。

大类的偏向因此落到了实处：

  • 力量武器偏重击。斧头可以飞掷回旋和处决，锤子擅长打被破甲的目标，个别锤暴击还能毁尸，只是得从别处补暴击率。
  • 敏捷武器偏攻速，主打快速连段与机动。
  • 智慧武器偏暴击，演示里的匕首基础暴击达到 15%，适合找弱点、快速连击和用毒。

观众眼尖，发现幻灯片表里少了 75% 智慧、25% 力量 这类混合武器。Hrishi 在问答里解释表没列全，法系武器的差异主要看自带什么法术、法术偏什么属性以及属性需求，光看基础攻击面板看不出来。至于力敏智三项均分的武器，当时还没开工。

既然大类靠动作和基础属性已经拉开了差距，固定词缀就可以省下来给个别底材做变化。演示里有一把纯火焰基础伤害的斧头，它前后两档同级斧头都只打物理，捡哪把全看你玩什么 BD。

另一把带破甲固定词缀的匕首则是给武器切换打配合的。演示版里吃破甲收益的技能大多在锤类，拿匕首先破甲再切锤砸下去正好接上。剧情里出现的这些特殊固定词缀，按当时计划都会有对应的终局高底材，不用一直捏着低级武器过日子。

词缀池拆干净，未切割宝石也换了掉法

法师拿法杖洗出一堆物理点伤，是一代做装最让人头疼的事之一。一代虽拆过战争长杖和符文匕首，Hrishi 还是嫌切得不够彻底。

二代演示里，施法魔杖和长杖彻底不出物理攻击词缀，改送一个不耗魔的自带技能。前期直接用来打伤害，后期有的杖能让下一发法术三连发，用来砸长吟唱大招特别划算。想抡棍子近身敲人，就去拿只出攻击词缀的格斗长杖，演示里还有比同类打得更远、模型也更长的底材（原片 27:01）。

2023 年原型里的陷阱也走武器分流：当时陷阱有独立于法术的陷阱伤害，双手投掷器具的底材定死投掷时间，装备词缀可以缩短它（原片 29:16–29:31）。换上手控引爆器具，任何陷阱技都能当地雷玩，省得再单做一颗地雷宝石，器具还能放副武器组，想布阵时再切出来。

不过这套按底材分感应和手动引爆的设计，到 2026 年做暗影时被团队放弃了。

权杖则彻底和近战锤分家，专门提供精魂（Spirit）和光环类辅助词缀（原片 31:15–31:54）。你可以主手拿权杖配副手盾打辅助，也可以主手拿输出武器、副手拿权杖养召唤。

原先占魔力保留的技能和常驻召唤物全改占精魂，装备上不再直接给 +1 僵尸数量，多招一只还是多开个光环全看精魂池怎么分。一旦切走副手权杖，它给的那截精魂一消失，靠它养着的常驻召唤物也会跟着散。

技能宝石掉落也换了思路。技能越做越多，靠怪刚好掉出你要的那颗太碰运气，全丢商店随便买，地上掉宝石又毫无惊喜。

未切割宝石（Uncut Gem）把选择挪到了捡起来之后：捡到一颗，就能在对应等级的技能池里任选一颗刻出来，而且等级跟当前进度对齐，想换招不用拿着 1 级宝石重新练（原片 33:17）。

混沌石一改，改造和重铸也留不住了

说回开头那两顶头盔，核心改动就一句话：新版混沌石改成随机移除并替换其中一条词缀，不再整件重洗（原片 35:33–36:45）。

通货 一代用法 2023 年展示方案 对地上掉落的影响
混沌石 整件稀有装词缀全洗 随机移除并替换 1 条词缀（不能自选，也不保底更好） 自带 3 条好词缀的掉落物起点高得多，点下去有机会把废词缀换成好词缀，当然也有风险洗掉核心词缀
改造石 抓着一件蓝装反复重洗词缀，再富豪变金 移除 堵死捡一件白/蓝底材站街猛点的老路，得继续从掉落里挑好胚子
重铸石 把装备洗回白装再点金重来 移除（问答确认） 防止绕道复现整件无限重洗

这样一来，开头那两顶同物等头盔终于分出了高下。已经有三条好词缀的那顶，点颗混沌石万一换走的是废词缀，立刻就能用上。一条好词缀没有的那顶，运气再好也顶多换上来一条，起步就不在一个档次。

光动混沌石兜不住。只要改造石还在，大家照样攥着同一件蓝装狂洗再富豪；重铸石还在，洗回白装再点金也能复现全盘重洗。

所以演示方案移除了改造石，问答里 Hrishi 也明确确认重铸石一起移除了。团队还顺着各类装备的词缀池挨个排查了一遍，避免别的重洗手段又把地上掉落的价值冲垮。

暗金该是谁的毕业装

Hrishi 评价一件暗金成不成功的标准很干脆：它该是某个人的毕业装，但通常不该是所有人的毕业装。

他挑了几件不同年代的例子来解释这个尺度。有一件低级暗金，对每个敌人的首次命中必定造成满时长冰冻。论整场秒伤它未必多好看，可如果你的构筑极度需要一个稳妥的先手控，知道第一下必定冻住，它就值那个装备位。

魔力构筑的拐点也很能说明问题。Hrishi 还没进 GGG 时，以玩家身份设计过 Cloak of Defiance，后来衍生出心灵升华大天赋。他还举了 Indigon，把魔力消耗直接转成进攻端的伤害倍率，玩家这才有了专门围绕怎么猛花蓝去搭构筑的理由。

再看 The Squire，盾面上那三个白色插槽最早是美术画的三个眼球状白孔，设计组顺着外观做出了真能插宝石的机制。同一天 Dane 还做了另一面自己觉得更帅的盾，就是后来让全服玩家评价两极的 The Oppressor。

矿坑头盔 Hale Negator 的早年故事刚好反过来：原本想做成耗魔回血，做完一试，发现和头盔自带的能量护盾打架，上线前只好换掉。

这个点子没浪费，后来挪到了天赋大点不可知论者（The Agnostic）上，点了就彻底不能用能量护盾。当年卡住头盔的冲突消失了，玩家自己也得算清楚这笔账：拿整条护盾去换耗魔回血，到底值不值。

9. ExileCon 2019 硬核机制问答：开发机现场拆解一代底层规则

原片：ExileCon 2019 《Game Designers Answer Your Hardcore Questions》
讲者：Mark Knewstubb、Rory Rackham、Mark “Neon” Roberts，主持人 Nick；现场配合 3.9 开发机实操演示，所有机制说明均对应 2019 年一代《流放之路》代码实现。

ExileCon 2019 这场硬核问答，三位核心机制设计师面前直接架了一台 3.9 开发机。观众提什么刁钻问题，能改数值的他们就当场改、当场放出来看。

第一个问题是：一次最多能射出多少支箭？讲者把这拆成了三个口径来答，分别是正常配装上限、程序整数上限，以及这台开发机卡死前的上限。

台上直接拿 3.9 新辅助 Arrow Nova 开测，效果是先把箭射到目标点再向四周放射。台下有人喊了 69，台上就在原箭数上加了 69 支凑成 74 支，接着数量翻倍，再往末尾添个零，开发机当场卡住，只能等它慢慢算完。

至于程序理论上限，32 位有符号整数最大能存大约 22 亿，不过离机器实际跑得动的量差得太远（原片 01:04）。

伤害转换为什么只能单向走

老玩家配装基本都背过这条单向转伤链：物理 → 闪电 → 冰冷 → 火焰 → 混沌（原片 10:16–10:50）。方向写死，是因为游戏里两条老规则同时生效：

  1. 物理转成火焰后，转出去的那份伤害同时吃物理加成和火焰加成。
  2. 如果能把 X 转成 Y，又能把 Y 转成 Z，同一份伤害可以顺着这条链接着转下去。

第一条是早年改炼狱之击时定下来的。当初炼狱之击把一部分物理转成火焰后，转出去的部分吃不到物理增伤，近战角色天赋树上点了一堆武器物理伤，一用这技能反而亏了一半加成，团队这才改成转伤保留原标签。

既然允许接力转，就必须强行规定先后顺序。假设 X 能转 Y、Y 又能转回 X，哪怕每次只转一部分，也会变成无限循环的无穷级数。

就算某些特例在数学上算得出收敛极限，也不可能在游戏实时算每个角色的通用属性时这么跑。团队也推演过换一套顺序或算法，但动一下就会毁掉一大批现有构筑，还会带出新问题，所以游戏里其他转换机制也都守着这条单向规矩，不绕回起点。

当时处理基础伤害计算的代码已经涨到了约 22,000 行。好在每次砍怪不用从头跑一遍，比如面板上的 Frenzy 物理伤，只要角色属性一变动，系统就算好存起来，命中时直接拿现成的数。只是实战里各种临时增益一叠，属性本身也在高频变动。

另一条容易看懵的词缀是 获得相当于非混沌伤害 X% 的额外混沌伤害（原片 24:30）。听着像只算一次，其实额外获得跟转换共用同一套算法，区别只在于算完新伤害后不扣原来的。而这里的非混沌只是简写，每一种非混沌类型都得单独算一遍：

  1. 设角色有 100 点基础物理伤害，身上带 20% 的非混沌额外获得为混沌，不计其他增减。
  2. 先把 100 物理全转冰，再把 100 冰全转火。
  3. 物理、冰、火三个阶段各自符合非混沌条件，分别按 100 点抽 20%，最后一共多出 60 点额外混沌伤害。

Rory 当时觉得这收益实在太高，还担心某些武器永远绑定多转几道的套路，把配装空间锁死。不过到 2019 年这场问答时，团队还没拍板具体替换方案。

命中结算的时间差与服务器 tick

恐惧之旗的护体逻辑很直接：插下旗子拿到护体那一瞬间就已经拍好快照，后面旗子状态再怎么变，身上的护体也不会跟着动（原片 04:31）。

攻速和服务器帧率的关系稍微绕一点。客户端渲染帧和服务器推进逻辑的 tick 是分开算的，讲者凭记忆说，服务器大概每秒跑 30 帧。

如果你一直按着施法键不松，上一招在一帧中途放完，服务器已经知道你还要放下一招，就会拿这一帧剩下的零头时间提前推进下一段动画，不必干等到下一整帧才起手。至于攻速快到一帧里要放两次以上会怎样，现场没实测，只记得以前测过会有一定效率折损，没给死结论（原片 21:03）。

闪现打击带一次瞬移，词缀写的附近到底算出发地还是落点？为了让结算和画面对得上，程序专门把这一击的伤害预测往后推了一点点，按固定三步走：

  1. 先把角色传送到目标敌人身边。
  2. 由代码强制通知光环，按新位置刷新作用对象。
  3. 最后再结算这一刀的命中伤害。

这套处理也不是一开始就有的。很长一段时间里，闪打根本不保证光环能在命中前刷出来，大概拖到 3.7.0 补丁周期早期，团队才给它补写了这段推迟预测、强制刷光环的代码（原片 51:31–52:00）。

3.9 合成怪的五个器官槽

当时 3.9 赛季 Metamorph 马上要上线，玩家对着五个器官槽问了不少细节（原片 13:45）。

设计师的初衷很明确，就是让你根据刚才在地图里见过的怪，自己拼一场想打的 Boss 战。如果只把五只怪的数值硬加，挑哪只都无所谓。但要是像枯疫涂油那样藏隐藏配方，玩家就会直接切出去查表，根本不管怪会什么招。

所以每个器官槽分配了不同职责的技能，把同一只怪塞进不同槽位，变出来的招也不一样：

  • 海岸图的僵尸带普通近战，用来补没有冷却的常规攻击空档。
  • 食人族扔火球，放到不同部位可能变成连续追踪投掷、范围火弹，或者让地面持续燃烧。
  • 吐刺怪提供短冷却狙击。
  • 脑部专管封锁场地，不少剧情 Boss 原本就有合适的技能。

界面会直接标出部位、技能名、奖励类别、能量条和相对加成，没有凑齐某五只特定怪给隐藏大奖的暗门。不过连发火球到底追不追人，还是得打起来才知道。

真正要小心的，是五个器官叠上去的伤害、血量和奖励倍率会和 地图词缀相乘，同一组器官放进高危红图，危险度直接翻倍。

现场还顺带答了两个小问题：

  • 为什么不在血条上标具体血量数值：组队队友进出时，有的 Boss 血量立刻变，有的得离够远或重进图才刷，硬贴一个假精确的数字反而误导人。
  • 选了 Daresso 的器官会不会带无敌：合成怪只会继承选中的那个技能，Daresso 转阶段的无敌不会跟着搬过来（原片 50:33）。

词缀里的附近、你，还有豪猪的死后尖刺

PoE 的词缀文案一直抠字眼。大家最常问的附近，英文是 nearby，它只保证有距离限制，具体半径每个技能、每件装备都不一样，还会吃天赋和装备的范围加成。

要想在悬浮框里直接显示当前角色的真实距离，UI 得能读取底层实时算出来的结果，当时这项工程还在排期队列里（原片 29:16）。

另一个容易踩坑的词是你，也就是 you 到底包不包括图腾和召唤物。原则上图腾放的是你的技能，召唤物通常不算。

麻烦出在早年为了给装备说明省一行字，不少本该写 your skills 的地方缩写成了 you。后面想修不能一键替换，只能逐条核对底层代码究竟认谁，比如当时的猎首就是专门补写了覆盖召唤物的说明。

问到豪猪死后炸出来的刺算不算攻击时，现场连设计师自己都先答错了一回，以为不算攻击，旁边同伴赶紧纠正：尖刺确实算攻击（原片 43:46）。

真正容易让人暴毙的地方在时间差。等刺飞到你脸上时，豪猪已经死了，它生前挂着的衰弱之类的诅咒通常已经跟着消失，除非你戴了能让诅咒留在尸体上的暗金。

就算讲清了结算规则，豪猪群同时炸屏几乎零预警的问题依然存在。设计师说以后如果重做，会多留点看清和走位的时间，但还是想保留那种让你出手前先提防一下的威慑力。

遇到意外构筑，GGG 怎么处理

玩家拿几件不搭边的东西拼出意外玩法，在 PoE 里很常见，台上聊了几个有代表性的案例。

苦痛之捷原本打算让毒蝎帮着本体一块输出。结果一位懂平衡的 QA 做了个 9,000 血的专家模式野蛮人，本体零输出纯靠蝎子打怪。Rory 劝他少点点血能让清图速度快一倍，QA 回了一句“可我这样不会死”（原片 41:47）。团队最后砍了数值，但保留了全权交给蝎子输出的玩法。

空手流和毁面者是另一种麻烦。毁面者给了空手极高倍率，后面每新做一个允许空手的近战技能，都得防着技能自带的点伤乘上毁面者直接失控。团队干脆把部分近战技能的附加固定点伤限死为 使用武器时生效，空手依然能用，只是吃不到那份点伤。

自动施法循环是受伤施放召骷髅配珠宝缩短寿命，再加上 Heartbound Loop 自伤形成的永动循环。设计师们其实挺喜欢这套玩法，只是当年到底料没料到，大家记忆不太一致。

蠕虫药水随时造怪触发击杀效果就棘手得多，该改药瓶还是改被放大的技能，台上也没达成一致（原片 33:49）。

反向击退真空吸怪图腾，做那双手套的设计师压根没想到图腾能把全屏怪吸到一起打。团队后来还是按计划改了通用机制，但专门新做了一件暗金把这种玩法保了下来（原片 49:20）。

另外有观众顺带问起图腾反射为什么没声音，讲者的回答是多半是音频 Bug，并不是故意调小。

复杂 AI 与底层代码成本

Warbands 赛季里，设计师费心给高阶怪写了协同逻辑：先看身边有没有低阶同伴，再决定冲锋还是固守。可普通怪进图一秒半就没了，高阶怪根本没机会打配合，连设计师都不确定玩家到底看出来没有，还有一回某群怪的两个行为判断顺序写反了。

更现实的限制是性能。一个实例里塞满怪、掉落和技能，服务器计算量暴涨，开锁步模式的玩家立马就能感觉到画面一顿一顿的（原片 36:15）。

早年还做过一个叫 Vortex Mine 的原型，本想把怪往中心吸、越靠里走得越慢。结果怪挤成一团，寻路一遍遍重算，加上当时锁步模式还没上线，客户端和服务器失步惨不忍睹，最后只能放弃（原片 48:18）。相比之下，玩家会盯着 Boss 一举一动看，把复杂 AI 留给 Boss 显然划算得多。

写底层功能有时也看运气。当年为钢铁之肤等技能写的瞬发机制，后面无数技能都在复用（原片 09:36）。

反面典型是暗金剑 Varunastra，装备上就一行 视作所有单手近战武器类型。为了支持这一句话，前后改了大概 13,000 行代码，逐项测试的工夫还没算在里面。

10. 把灵体投掷减速到零，怪撞上去会掉血吗？

原片：ExileCon 2023 第一天奇葩机制问答（YouTube 7:58:24–8:52:46）
讲者：Chris Wilson 主持，Mark Knewstubb 操作开发端，与 Mark “Neon” Roberts、Andrew Ettles 同台；500 枚投射物、百倍体型变化均由开发工具强行拉出，正常配装无法复现。

玩灵体投掷的时候，很多人大概都想过一件事：把投射物减速堆高，飞刀就能在怪堆里多磨几段伤害。那要是减到 100%，把刀彻底定在半空，岂不是白得一个永久悬空陷阱？

ExileCon 2023 第一天压轴的奇葩机制问答里，Mark Knewstubb 直接在开发机上试了。这场五十四分钟的问答看着像几个人开着作弊器乱折腾，但一连串实测跑下来，反倒把不少平时看不见的底层限制逼了出来。

刀停了，碰撞检测也跟着停了

面对 100% 投射物减速的问题，台上先把速度降了大约 95%，接着继续往下压，结果飞刀慢得像乌龟，就是停不下来（原片 8:15:33）。Mark 解释，程序给投射物速度硬加了底线。

早年版本里真出现过彻底静止的投射物，但结果出人意料：怪物自己走过去撞在刀刃上，一滴血也不掉。

原因出在碰撞检测的写法上。游戏每次移动投射物，才会沿着它刚走过的那一段线段扫一遍有没有碰上目标。如果投射物纹丝不动，位移是零，碰撞检查就不会触发，哪怕怪物和刀完全重叠也打不出伤害。所以飞得极慢能多刮几下，真归零了反而失效。

接着 Mark 把速度恢复正常，把投射物数量拉到 500 枚，屏幕很快被弹幕盖满，根本看不出原技能长什么样。

台上开玩笑说新 Boss 招式就是这么来的，其实还不算瞎说。开发时真常这么乱试，给怪招狂加施速或投射物，有时能蹦出适合玩家用的点子，把玩家技能参数拉爆也能摸出 Boss 技能的雏形。第一批瓦尔技能里的瓦尔电弧和瓦尔火球，还有后来的瓦尔熔岩之击，都是从这种硬拉参数的原型里挑出来精修的（原片 8:06:00）。

至于 500 枚投射物到底卡不卡，开场那段空地与假人对比已经给过答案：得看往哪儿扔。对着空地猛放，客户端和服务器只需算飞出去的轨迹，看着还挺顺。一旦切到摆满假人的场景，命中判定、连锁跳转和高频施放的开销一块压上来，帧率马上就掉下来了。

一代转伤吃双加成，二代改回了只吃转后类型

聊到物理转冰冷为什么还吃物理增伤，Mark 把最早那三种元素武器攻击的历史翻了出来（原片 8:08:01）。一代最初确实是转完冰冷就只认冰冷伤，但早年天赋树上的武器节点几乎全加物理，点了一堆武器天赋再玩元素攻击，点数大半都废了。

把三种计算思路摊开看一眼就能看出差别：

方案 计算方式（例：100 物理全转冰，物理/冰伤各 +50% increased） 结果与问题
转前算物理、转后算冰冷 100 × 1.5 × 1.5 = 225 原本同属相加池的 increased 意外相乘，膨胀失控
全算完加成再转换 算加成时仍是物理，吃不到冰伤 装备上的冰冷增伤全部失效
一代最终方案（先转、留原标签） 100 × (1 + 0.5 + 0.5) = 200 两项相加不乱乘；多次转换记沿途类型，但须单向防循环

2023 年现场试玩的《流放之路 2》又把一代早年放弃的方案捡了回来，转成冰冷后就只吃冰冷加成（原片 8:11:15）。因为二代天赋树的武器节点不再只加物理伤，当年逼出一代做双吃的原因已经不在了。

防守端的“受到的火焰伤害视为冰冷承受”则是另一套逻辑。玩家火抗低、冰抗高，找这条词缀就是为了用高冰抗扛火伤。要是承伤转换也保留原来的火伤标签，这条词缀就没法帮角色绕开短板了。

无限连锁清不完一整张图

观众抛了个脑洞：把连锁次数和搜索范围全改成无限，一发技能能不能把全图清光？答案是单人绝对做不到（原片 8:18:02）。

游戏为了省算力，只有玩家周围一定范围内的怪才处于激活状态。搜索范围写到无穷大，也搜不到地图另一头还在休眠的怪。台上有人开玩笑说，那要是在全图站满玩家把怪都唤醒呢？这个现场没测。

退一步讲，就算全唤醒了也未必打得中。拿电弧点排成一队的假人，电流能一路跳过去。可换成需要飞行时间的投射物，每次转向只锁目标那一刻的位置，然后直着飞过去，距离一拉长怪早就走开了，或者半路直接撞在墙上。就算带地形连锁，地图最外圈的边界到底算不算可反弹的墙，台上几个人也没给出准话。

顺着“站满全图要多少人”的话题，他们还聊到了地图人数上限。早年程序用一个 32 位整数 当掩码，记录每块地形对哪些玩家可见，一人占一位，所以单实例上限卡死在 32 人，城镇平时压在 24 人左右。

后来做大逃杀模式重写了这块，实测跑过 100 人同屏。再往上加就得先过客户端这关，一百套不同流派的技能特效全得预加载，网络同步的数据包也会越滚越大。

几道得翻代码才讲得清的现场提问

为什么不直接把“附近”标成具体米数

把内部单位换算成米本身没有难度，比如台上提到某项升华的附近就是 60 个内部单位。

麻烦在于一代很多半径是硬编码在各自技能代码里的，UI 没法像读普通属性那样直接抓出来。想改就得把老技能逐个迁移，还要验证半径被词缀动态放大后，面板数字会不会跟着正确刷新（原片 8:21:46–8:23:31）。

二代资产与服务器扩容的反哺

两代共用引擎，怪物和 Boss 的骨架、动作、特效早就互通了，禁忌圣域的石像守卫用的就是二代资产。唯一几乎搬不过去的是玩家职业模型，因为牵扯一整套配套动作。

服务器架构也是共用的。一代峰值在线约 35 万人时已经挺吃紧，为二代百万级并发做的扩容会先放到一代里压测。另外当时所有网关共用登录队列，法兰克福一堵全球跟着排，团队正在改成各网关分开排队（原片 8:25:16）。

伤害堆成负数会不会给怪回血

卡兰德湖能把戒指词缀数值反转，如果粗暴地给附加伤害上下限同时乘 -1，上限就会比下限还小。所以上线前，团队专门把戒指词缀逐条过了一遍做单独处理。

退一万步讲，就算面板上真凑出了负伤害上限，底层传伤害用的数据包是 无符号整数，进结算直接归零，不会给怪加血（原片 8:26:45）。

瓦尔尸体爆破的 22 具上限

测到全图铺满几屏尸体、瓦尔尸体爆破能不能一路炸完时，先出了个插曲：Mark 拿开发工具刷怪太猛，直接被服务器防异常机制踢下了线。

重连铺好满地尸体一炸，没炸几步就停了。几个人现翻技能说明才确认，连爆间隔会越来越长，而且演示版里硬限制了最多炸 22 具尸体。他们隐约记得早年好像没这上限，但实测还是按 22 具算（原片 8:27:31–8:29:30）。

把小怪放大六倍当不了 Boss

体型实验先往小了调。把角色缩小 99% 再配高移速，屏幕上彻底看不见人，只能盯着水面踩出来的水花猜自己跑哪儿去了。往大了调，老猎首玩家早年倒是见过，以前角色体型没上限，叠多了满屏幕只剩一双膝盖，后来才封了顶。

接着台上把海滩上那只吐刺小怪直接放大，本体大得像座山，嘴里吐出来的刺还是原来那么一丁点。

拉大模型缩放比例，不会自动放大弹丸、步幅、移速或者动画节奏，人形怪拉大之后迈一步，双脚甚至会在半空悬停好半天。偶尔有怪放大了碰巧看着还行，绝大多数想当 Boss 还是得老老实实重调动作和技能。

后面观众点名看 Boss 大乱斗，实测下来反倒验证了为什么 Boss 离不开原生场地（原片 8:35:01）。开发测试区虽然加载快、能随手召怪，但把正经 Boss 拽进来，缺胳膊少腿的问题全冒出来了：

  • 剧情版 Oak 绑定了盗贼任务脚本，空地里没法直接打，得另挑能独立召唤的版本。
  • 硬召出来的 Argus 稀有度不对，血量和伤害矮了一截，打赢打输都说明不了正常强度。
  • Searing Exarch 与 Eater of Worlds 的大招全依赖各自的专属竞技场、启动触发器和场地机制，扔进白板空地连招牌招都放不出来。

为了看清混战，台上开了拍宣传片专用的自由镜头，一拉角度，平时俯视角下藏起来的远景和雾效全穿帮了。打到最后，一个调试断言直接把整个实例挂死，两位终局 Boss 终究没分出胜负。

骷髅大军刮痧，还有最让程序头疼的水球

台上召出一整屏骷髅围殴 Argus，密密麻麻看着吓人，血条掉得却像刮痧（原片 8:48:16）。几人一看就笑了，开发工具默认召出来的是低等级骷髅，数量再多，单只伤害摆在那儿也没用。

聊到召唤物时，他们顺带提了句 Fresh Meat 辅助的来历。Crucible 赛季里有些幽魂和僵尸刚召出来头几秒猛得离谱，团队不想把整棵武器天赋树搬进核心游戏，干脆把这套爆发做成了通用辅助宝石留下来。

最后有观众问，做过这么多奇葩机制，哪一个最让程序难忘。答案是水弑界（Hydrosphere）。这颗水球属于玩家阵营，玩家自己得能打中它来触发连锁或溅射，敌方怪物却不能攻击它。

在此之前，游戏筛目标基本只查一次 是不是敌对阵营 就完事了。有了水弑界，代码被迫拆成两步问：先查它属于哪一方，再查这次出手的人到底能不能打中它（原片 8:51:16）。

结束前他们还提了个当时已知、准备上线前修掉的先祖试炼 Bug：连开两局时，上一局留在地上的尸体和召唤物没清干净，下一局一开打，场上已经躺着上把的残留。

11. ExileCon 2023 开幕专访：Jonathan Rogers 谈《流放之路 2》的战斗与配装

原片：ExileCon 2023 第一天开幕后专访（3:58:15–4:23:15）｜讲者：Jonathan Rogers｜时间：2023 年 ExileCon 第一天

ExileCon 2023 开幕演示刚播完，玩家群里吵得最凶的就是那把双手大锤，挥一下从蓄力到收招拖得很开。一代刷习惯了的人看完多少有点发怵：以后辛辛苦苦配几百个小时的终局号，挥一锤也要等这么久吗？

开幕结束后的专访一上来，主持人就把这个问题抛给了 Jonathan Rogers。

展示看起来很慢，真正要压的是极端上限

Jonathan 先稳住了老玩家的情绪：团队真正想压下去的，是少数快到离谱的构筑，大概排在第 95 百分位上下、各种倍率已经乘了好几轮的那一批。

开幕演示故意挑了慢速双手武器，纯粹是为了让第一次看二代的人能看清角色动作，不能拿它直接套普通配装平时刷图的节奏。

他拿投射物举了个直白的例子：一秒钟打出 600 枚，屏幕全糊成一片，连 Boss 抬手放什么招都看不见。压到一秒 60 枚，场面照样够热闹，好歹还能看出下一招从哪来（原片 3:59:45）。

这两个数字跟帧率预算无关，60 也不是打算写死的硬上限。

玩家最担心的还是把机制串成连锁的乐趣没了。Jonathan 说自己也爱看触发、多重施放和各种技能连招，还开玩笑说只要别把服务器点着就行。

他在意的底线很具体：连招满天飞的时候，玩家还得能看清 Boss 动作，跟着调整站位和打法。

为了让慢武器用着不憋屈，动作手感上补了两道保险：

  • 起手之后还能重新瞄准，或者直接翻滚取消。刚举起锤子发现脚下出红圈，可以先收招保命，硬打完还是先闪开变成了一个临场抉择。
  • 位移技能尽量留给接敌。像武僧的 Killing Palm 能从老远直接突到怪脸上，但落点必须有怪。清完一片继续赶路时，就不用为了跑得快对着空地一路按技能（原片 4:14:45–4:15:30）。

药剂也是同一个路子。解燃烧药剂得等身上真着火了再喝，才会清掉燃烧并给一段短暂免疫。站在安全区提前灌下去，一点保护作用也没有（原片 4:06:01）。

Jonathan 很讨厌五瓶药轮流按一遍就常驻增益的玩法。在他看来，那等于腰带上多出五条被动词缀，只是逼玩家每隔几秒手动续一次。

主持人当场提醒他一代已经出过类似词缀，Jonathan 挺坦白地回了一句，最近一门心思扑在二代上，对一代近期的改动确实不太熟。

加进金币，是为了填补战役掉落的空档

《流放之路》十来年一直靠通货以物易物，突然宣布怪物掉金币，老玩家第一反应多半会皱眉。

Jonathan 给出的理由很实在：清完一群怪什么也没掉，玩着总归扫兴。可要是每只怪都掉一件得停下来看词缀的装备，跑两步就得低头翻垃圾，刷图节奏立马就碎了（原片 4:02:01）。

金币就是来补这块空档的。路过捡起来一点点攒着，不用停脚鉴定。

按当时的战役设计，推图时缺火抗可以直接回城找商人买件过渡装。商店会随进度补新货，旧货也会留一阵，不会刚升一级，刚才相中的那件装备就刷没了。手头宽裕的时候，还能挑个底材赌一把，买之前不知道出什么稀有度。

这套机制 GGG 之前拿 Ruthless with Gold 做过一次小规模试水。Jonathan 很清楚，在办公室打一两张图只能测出捡金币方不方便，真要看玩上几天手里会攒下什么、最缺什么，必须放进大群玩家里跑一跑才知道。

主持人自己就踩过那次试验的坑。当时关了商店通货兑换，他包里攒了几百颗工匠石，想凑几颗链接石却费了老大劲。

团队知道金币看着不太像传统《流放之路》，但定位划得很死：只用来补战役掉落，不会取代玩家之间原本各有制作价值的通货。

光环改吃精魂，魔力终于留给放技能

聊到配装资源，Jonathan 先把一代的魔力保留吐槽了一遍（原片 4:07:15）。一代里开光环和放技能啃的是同一管蓝，哪怕明知道多留点魔力不容易断蓝，配装时大家还是忍不住压到只剩一丝，总觉得不压到底就亏了伤害。

二代把光环挪去保留精魂（Spirit），开发团队才终于能单独调主动技能的魔力消耗。

精魂当然不是白送的。光环、常驻召唤随从和自动触发技能全挤在这一池子里，给哪头多留一点，另一头就得缩水。按当时的构想，能带几只僵尸主要看你肯分给它们多少精魂，团队打算尽量少设随从数量的硬上限。

想专心玩召唤，换把加精魂的权杖就能多带几个小弟。不过权杖并不归召唤师独占，它还带强化附近友军的词缀，近战角色完全可以主手拿连枷、副手配一把权杖，想多开光环的流派同样可以专门堆精魂（原片 4:09:01）。

Jonathan 现场口头报过几个测试数字，紧接着自己补了句别当真，当时定死的只有三类玩法共用精魂这条规则。

主持人替纯召唤玩家问了句很具体的问题：只想一直翻滚躲技能、全让小弟打，二代还行不行？Jonathan 觉得慢慢磨大概也能打死，但如果你肯带一两个跟小弟配合的主动技能，收益就应该给得够明显，让玩家自己觉得按这一键挺值。

六连绑在技能宝石上以后，配装怎么算账

演示方案里，每个主动技能天生带 2 个辅助位，最多扩到 5 个，也就是六连（原片 4:12:31）。六连照样值钱，只是体验从对着胸甲狂点几千颗链接石，变成了等一颗稀有的扩孔通货，只要打出来就百分百成功。

装备孔色没了，洗幻色石的折磨也跟着消失，但配装限制换了个地方冒出来。当时的方案会把所有辅助宝石的属性需求加到一起算，敏捷职业想带好几颗智力辅助，省下了洗异色孔的工夫，却得在装备和天赋上凑出足够的智力。

攻击和法术的成长曲线也往中间靠了一步。团队打算让攻击技能更吃宝石等级，让物理和攻击流派也有动力追高等级宝石。施法职业则比过去更看重武器上的属性，当然攻击流派整体上还是更吃武器面板（原片 4:16:45–4:17:45）。

这样一来，拿到稀有扩孔通货先给谁升六连、带跨属性辅助够不够属性点，都成了进图前要盘算的功课。

针对大家对九个技能位的担心，Jonathan 也补了一句：真不用每打一波怪都把九个键轮流按一遍。有些平时偶尔救场的功能技，现在也能痛快给它配齐辅助，留在栏位里专等关键时刻用。

跨作商城外观与老赛季怎么回归

两作分开运营，老玩家最关心的莫过于一代买过的商城外观怎么办，以及一代以后会不会被放生。

Jonathan 把这两件事绑在了一起：今后卖出的商城外观和赞助包只要两作通用，继续更新一代对公司就有实打实的商业回报，这比嘴上发誓绝不放弃老游戏靠谱得多（原片 4:21:00）。

主持人还惦记着一代早期竞赛奖品那些绝版造型。Jonathan 划清了界限：仓库里的实体物品不能直接套这套规则，必须先能转成商城外观、进到衣柜里，才算跨作外观。

至于一代的老角色和经典赛季，主持人在演示里一眼认出了 Alva。Jonathan 想把不少经典机制改过再放进二代，但没法直接照搬。旧粒子特效摆在新画面里太扎眼，得重做；人物还得顾上两作相隔的年头，Alva 会时间旅行，正好算个例外。

其他零碎问答

专访中间还答了几个玩家比较关心的小问题：

  • 被问到二代里的新西兰本土元素时，Jonathan 提了以卡鲁人为主角的一幕，还有岛上那些在其他游戏里不太常见的本地植物（原片 4:04:45）。
  • 游戏模式方面，团队确认保留硬核和 SSF（独狼自力），二代刚起步时暂不单开 Ruthless。理由很现实：联机模式得有足够多的人撑起经济，SSF 本来就不找人组队，单独开出来对人数分流的影响小得多（原片 4:20:01）。
  • 至于为什么要一口气做 12 个职业，Jonathan 笑着交代，一代原来的职业格子怎么看都放不下德鲁伊。团队后来拍板每种属性组合各做两个职业，很大程度上就是为了把德鲁伊放进来（原片 4:23:02）。

至于为什么删贵族、小号凭什么重跑战役，以及只想按两键刷图行不行这些更尖锐的追问，都留到了第二天的四人问答。

三、世界观与叙事

12. 《流放之路》的世界观怎么落到物件上：Erik Olofsson 分享整理

资料来源：2013 年《流放之路》第三章扩展前后的 GGG Developer Video 1、ExileCon 2019 主题演讲 Building the World of Path of Exile，以及 ExileCon 2019 首日 Amie 现场专访。讲者为 GGG 联合创办人 Erik Olofsson。2019 年提及的 4.0 是《流放之路 2》当时的内部代号，下文会区分当时已能实机演示的内容与尚在构想的计划。

很多玩家对《流放之路》美术的第一印象是又黑又脏。不过黑和脏很容易浮在表面，给石头糊一层青苔、把滤镜压暗，谁都能做。

翻完 GGG 联合创办人 Erik Olofsson 跨度六年的三场分享，他反复强调的其实都是具体物件上的细节：雨水顺着石像的折痕流下来，泥垢该积在哪道凹槽里；角色弯腰时，金属胸甲怎么动才不会像橡胶一样拉伸；一件暗金装备遮掉风味文本，单看图标还能不能撑起它的来历。

2013：暗金装备的图标、文本与词缀

最早这段短片录在 2013 年一代第三章扩展前后。当时担任美术总监的 Erik 想让玩家捡到暗金装备时，觉得这是游戏世界里真正存在过的旧物件。

所以每件暗金的图标、风味文本和实际词缀，他都会亲自过目，重点看三样东西能不能互相印证。他在片子里举了个没起名字的例子：一件属于某位死去英雄的暗金，就算把那几行纪念文字遮住，光看图标造型也得对得上那段来历（原片 0:17–0:45）。

同样的思路也用在了第三章扩展的高塔里（原片 1:00）。玩家从塔底一层层打上去，穿过昔日帝国的权力中心，最后在塔顶撞见当年流放自己的人。复仇这件事不用靠大段过场交代，爬塔的过程本身就在讲故事。

2019：先给开阔地，再进密林

到了 ExileCon 2019，Erik 回忆起车库创业时的规矩：玩家从注册账号到真正动手打怪，最多只能花 5 分钟。开场最要紧的是让你明白自己眼下的处境，至于这个世界的国度、宗教和帝国兴衰，完全可以放到后面慢慢展开。

2019 年《流放之路 2》演示一开场的绞刑只给了一句判词。Erik 借这个镜头解释了团队口中的 dark and gritty：哪怕你死在绞架上，周围的人照样过日子，这个世界并不在乎你。先有一个足够狼狈的起点，后期强到能一波清屏时，成长的反差才拉得开。

现场有观众问绞架是谁立的。Erik 解释二代换了时代和地界，开场位于地图右侧一座小岛上的艾兹麦（Ezomyte）社会；一代玩家当年的选择过了二十年会引发什么后果，团队打算让你顺着剧情自己撞见（原片 2:15–3:16 · 40:30）。

从绞架逃生后，角色在泥泞的河岸醒来，很容易让人想起一代海滩上捡根木棍敲螃蟹。二代河岸配了细雨、湿泥和扫描回来的歪树，效果如下。

Erik 在问答里解释了这段节奏安排（原片 29:32）：先让你走过视野开阔的河岸和伐木营地，等一脚踏进密林、视野突然收窄，压迫感才出得来。

重做森林还有段旧事。当年做一代时，他们最早动手做的是第二章森林，特意等攒了点经验才回头做开场海滩，结果森林成了全游戏最老的一批资产。到了二代，原本强盗扎堆的林子，干脆改成了听得见嚎叫、随时会撞见狼人和女巫的险地。

河岸上晃荡的僵尸看着眼熟，重做起来其实挺费工时。一代更新这么多年，僵尸攒了一大堆动作和技能，换新骨架后全部都得兼容；团队愿意花这笔成本，是为了以后再给僵尸加新招时更省事。

旁边的营地则是另一道考题。它既要看着像个被围困的据点，又不能只有一个固定出口，演示里有时左上角的门关着，就得绕去右上或右下出营地。

按 2019 年的方案，每个角色会生成一张世界地图，单个关卡的随机布局得跟它对齐。对场景美术来说，三个方向都得做成正经大门，不能只修一条漂亮主路，再拿木板随便堵上另外两个出口（原片 5:30–7:32）。

实地扫描、模块化荆棘与不等高的墙

给哥特墓园的石头加青苔不难，难的是让污痕长在对的位置：雨水顺着雕像哪道折痕往下流，泥垢就该积在哪个凹槽里；旁边那块常被雨水冲刷的石面，反而该比周围干净一圈。

这种自然风化靠手画太费劲，直接从真石头上采样更靠谱。新西兰本地找不到他们想要的欧洲中世纪古墓，GGG 就走了一套跨国扫描流程：

  1. 请波兰团队去欧洲实地做摄影测量（Photogrammetry），绕着真墓碑和雕像拍一圈照片，重建高模。
  2. 交由另一家外包公司做减面，修补自动重建留下的瑕疵。
  3. 整理成可用资产放进游戏场景。

对照墓地扫描画面看，连石头上雨水冲刷的痕路都留了下来（原片 11:34）。

狩猎场里的旧石墙、卵石路和树干同样是实地扫描的，攀在墙和树上的荆棘由美术用模块化工具铺上去，草地配了预计算光照（原片 12:01）。真石头自带风化纹理，但不会自己找位置，哪堵墙立在哪儿、荆棘怎么从石缝爬上树干，还是得靠场景美术把零散扫回来的物件统一进同一片林子里。

到了章末庄园，还能看到一处迁就俯视镜头的处理（原片 12:55）：靠屏幕下方、离镜头近的墙修得矮，角色贴着墙根跑也不会被挡住；屏幕上方的墙正对玩家，砌多高都不遮人，大宅的体量感全靠这面墙撑起来。这批庄园构件很多是 GGG 画完设计图、外包建模，最后由内部环境美术拼装成图。

台下有观众发现演示画面视野开阔了不少。Erik 确认他们确实拉远了相机，还去掉了早年的鱼眼变形，性能没有掉，从新视角看墓园，透视也更接近老式暗黑类动作 RPG 的观感（原片 46:16）。

角色、骨架与盔甲一起重做

Erik 最早画的那三个主角压根没起职业名，就叫力、敏、智。隔了这么多年重画，有一条原则没变：选人界面扫一眼，玩家就该猜出这个角色怎么打架（原片 17:32）。

  • 野蛮人沿用了卡鲁族元素，原本概念稿配的是绿色玉饰，建模时改成了更贴合力量属性的红色。
  • 游侠整体轮廓改动不大，主要靠跳跃和移动姿态体现敏捷。
  • 女巫折腾了好多稿，最后还是退回了最初那个瘦弱身板，放在瓦尔克拉斯这种残酷的环境里，瘦弱反而最显眼。

把镜头推到女巫脸前看材质，皮肤、眼唇和头发对光线的反馈完全不同（原片 19:25）：眼睛和嘴唇比脸颊湿润，用的是范围和锐利度各异的高光；头发单独走了另一套方案，美术用流向贴图（Flow Map）控制反光，让高光沿着发丝方向分布。

骨架重做也一并清了不少一代留下的旧账。老玩家大概记得一代圣堂武僧是左撇子，经常闹出装备戴反、技能特效往另一侧飞的问题；各职业骨架又不互通，一套动作想给别的职业用非常费事。

新骨架把时序和控制方式统一了，Erik 在台上当场把贵族的动作套给了圣堂武僧。连跑步也改了，一代只是把同一段慢跑加速播放，新系统会在三档速度的动作间混合过渡，喝下水银药剂，角色会直接压低重心切进冲刺姿势（原片 42:31）。

说到盔甲，Erik 的标准是看着像能摆进博物馆的真东西，从低级破甲到高阶板甲，做工档次一眼要有区别。他甚至设想过在背包里拖动装备时带点碰撞声和轻微回弹，不过这当时还只是留着以后琢磨的点子。

排期上，团队派了专人负责非商城装备，先做齐基础底材，再轮到暗金装备的专属模型。一代的商城外观也会兼容进二代，肩甲该不该晃、晃多大弧度，按每件造型单独调（原片 45:45 · 48:15）。

Glorious Plate 的返工是个很典型的例子（原片 23:25）。初版人物一弯腰，整块金属胸甲跟着肚子一起拉伸弯曲，像橡胶一样变形。团队把它拆成三片刚性甲片，人物弯腰时甲片之间互相错动滑动，每一块金属本身保持不变形；肩、肘、膝这些关节处再补细骨架，护甲就能贴合关节运动。

布料走另一套方案：袖口随动作摆动，披风同时受物理模拟和角色动画驱动，下摆自然垂坠，上端依然稳稳贴着肩膀。当时主副色遮罩系统也已经搭好，至于以后怎么开放玩家染色、能不能切换湿润或金属质感，Erik 坦言还没拍板（原片 25:01）。

高速刷图时，环境细节与战斗可读性的取舍

台下有观众问得很实在：终局玩家开着一圈光环高速冲过墓园，费劲扫描的石像雨痕还有人看吗？

Erik 倒挺看得开。第一次开荒的人步子慢，喜欢翻剧情线索的玩家本来就会停下来逛；急着赶路的人照样可以一路狂奔，哪怕只瞥一眼环境、听一句 NPC 招呼，也能马上反应过来自己到了哪张图。

声音在这块帮了不少忙：踩在不同地面上脚步声会变，走近树林才听得见鸟叫，怪物也不光会战斗嘶吼，平时还有别的声音（原片 26:32 · 30:01）。

按 2019 年的计划，一代老战役也会逐步换上新材质，翻新金属反光、湿润感，甚至让兽腹看得出搏动。改动会先从绝望岩滩和狮眼守望这些开局地图开始，藏身处要是用了同一套地块，也会跟着更新（原片 49:15–51:00）。

不过视觉细节终究要给战斗让路。你可以错过一段背景故事，但不能看不清要命的攻击。终局地图会少摆容易卡脚挡路的碎石；做技能特效时，还得专门测高攻速下会不会糊住怪物。Erik 拿爆炸举例：起爆那一下可以耀眼，紧接着就得迅速散开，把怪物接下来的动作露出来（原片 38:30）。

还有观众问，GGG 会不会像《暗黑破坏神》的奶牛关那样做点恶搞彩蛋。Erik 说他们真动过念头，聊过一个赛博朋克版的《流放之路》，最后还是毙了。删掉废案不难，可一旦某个玩笑打破了第四面墙、改变了玩家看这个世界的眼光，以后再走进同一片严肃的场景，可能就再也没法当真了（原片 51:31）。

专访补充：美术、玩法与产线配合

在首日 Amie 主持的直播专访里，Erik 聊到了不少美术和玩法互相配合的例子。

拿那只扛大钟的怪物来说，本来是美术画了口钟，大家看着稿子突然冒出一句“这玩意儿能拿来当凶器”，玩法组这才把战斗拆成两段：先空手打一阵，打到一半怪物跑去扛钟。反过来的情况也有，策划在实战里觉得怪缺一招逼走位的攻击，回头找美术给它添件武器（原片 6:45:45）。

狼人同理，本来只是森林怪物，等角色骨架支持跨形态变身后，直接启发了玩家的变身技能，刚好同期的蜕变联盟也在做变形。

预告片里那座移动城镇是由一列大篷车拼起来的。主线往前推，车队会驶入不同沙漠、遇上不同天气，本来冲着古墓去，半路刮起沙暴，整座城都得跟着掉头。至于片尾一闪而过的那艘船，Erik 坦言当时还没做到车队这种交互程度（原片 7:00:18–7:01:03）。

做一个普通 NPC，起手可能就一句话加一堆参考图，画几张到十来张草图挑出好记的特征再建模，进游戏后还要调配色、看加完特效显不显眼。但赶赛季时玩法经常定得很晚，美术等不起，3.9 那会儿就是直接从已经在做的库存角色里，挑了个最像炼金术士的，照新赛季需求重新调色（原片 6:49:01）。

验收这块，Erik 管头尾，中间交给资深美术盯着。终审时把角色、宣传图和标志摊在一块，既要看着像同一个赛季，又得跟上个赛季拉开区分。

被问到有没有因为太血腥而被毙的原画，他说新引擎早就能把血肉做得很逼真，但很多东西藏在暗处没看全反而更渗人，没必要每个房间都直愣愣地把血肉摊在眼前（原片 6:53:02–6:53:49）。

引擎升级也松绑了不少老限制。早年给随机地牢摆灯很麻烦，两盏灯拼太近画面就会出黑块，偏偏摆灯的人根本不知道随机生成器会把哪块拼到隔壁；等引擎能扛更多光源了，美术才敢试以前不敢碰的布光（原片 6:55:30）。

音频组则受益于二代更宽裕的周期。以前赶赛季录音总排在管线最末尾，有时上线前只剩几个小时收尾，现在终于能把排期往前挪，专门跑去新西兰河边和海滩实地采音，让游戏里留着当地的声音（原片 7:05:16）。

专访最后 Amie 问招美术看什么，Erik 的要求很具体（原片 7:08:18–7:09:30）：

  • 作品集里看重肖像、解剖、色彩和光照习作这些基本功。
  • 借现成三维模型辅助没问题，但自己得有眼力看出毛病：怪物胳膊画短了，进游戏就够不到玩家；衣领和盔甲卡死关节，原本想好的大招根本摆不出来。
  • 概念画师不能交完图就撒手，得回头看一眼建出来的模型，理解偏了还来得及商量。

团队人一多，GGG 还专门搭了个内部网页，每件资产谁在干、走到哪一步，打开就能查。

13. 玩家不按剧本走时，Matt Dymerski 怎么给《流放之路》写剧情

原片：ExileCon 2019《Storytelling in Path of Exile》（Matt Dymerski 主讲） · ExileCon 2023 首日专访（KittenCatNoodle 访谈 Matt Dymerski，7:05:43–7:27:36）

玩 ARPG 的时候，很少有人会老老实实照着编剧排好的顺序走。

《流放之路 2》早期演示里就出过这么一件事：蒙面人还挂在树上等人救，有些玩家压根没跟他说过话，绕了一圈先把救他用的符文捡回来了。这时候如果还按原剧本演，让蒙面人开口请你去找符文，双方一照面马上穿帮。

首席编剧 Matt Dymerski 在 2019 和 2023 两届 ExileCon 上都聊过这类问题。2019 年那场他结合一代和当时还叫 4.0 的二代演示，讲怎么把剧情和任务状态写扎实；2023 年在 KittenCatNoodle 的直播专访里，他又顺着二代的新进度，聊到怎么处理玩家跳过对话甚至整幕不理某个 NPC 的情况。

刚进村的时候，别把设定全倒给玩家

Matt 判断玩家能吸收多少剧情，第一步看游玩时长。玩过上千小时的老玩家都还有没搞清的细节，刚进游戏的新手更顾不过来：眼睛该往哪儿看，地上能点什么，角色怎么落到这儿的。连移动都没摸清时，再华丽的开场白也听不进去。

2019 年演示的开场画面很克制，新手引导按条件分层触发（原片 03:01–03:21）：

  • 刚开局视野里只留一根金色箭头，直指地上可以捡的装备。
  • 原地发呆满 30 秒 才会弹出左键移动提示，大多数人根本见不到。
  • 喝药提示同样藏在条件后面，非得血条见底、而且一次药都没喝过，游戏才会暂停一下，让玩家按一次药瓶。
  • 真正绕不开的硬门槛放在升到二级：必须把天赋点点了，城门才会打开。

进了营地之后，话题也是慢慢放出来的。镇子里其实备着十几个可解锁的对话选项，但头一回进来不会全摆上台面。

在 05:16 的营地演示 里，玩家刚踏进村口就会撞见 Renly。他特意站在其他可交互物件前面，先把营地眼下出了什么状况讲清楚，说完才退回平时干活的位置。

后面的对话选项全靠玩家行为解锁。见过 Finn 再去跟 Oona 搭话，菜单里才会多出关于 Finn 的问题；读过墙上的布告，才能回去问 Renly 发公告的伯爵究竟是谁。

对于一路点掉对话的急性子，任务追踪栏一样得把路指清楚。Matt 拿一代典狱长 Brutus 的任务状态表举过例子（原片 08:15），光是进监牢、打死 Brutus、通往下一张图这几步，背后就拆出了十几种先后组合：

  • 先钻进监牢，还是先接任务。
  • 前期奖励领了没有。
  • 刚见到 Boss，还是已经打死。
  • 过没过 Prisoner’s Gate。
  • 最后那本技能书，揣进包里和已经吃掉也算两种状态。

到了 2019 年演示里挂在树上的蒙面人，任务状态直接涨到了 23 个。哪怕昨晚跳过所有对白、第二天上线全忘光了，任务栏也得照着角色此刻的真实进度，把下一步写明白。

同一个人，也有只顾着赶路的时候

除了玩了多久，Matt 还会看玩家当下在意什么。有人爱翻年表考据，有人只盯着每小时刷图收益。这和资历关系不大，同一个人换个阶段心态就会变。

Matt 自己练级时也是一路狂奔，等满级喘过气来，才静下心翻文本。所以他把游玩时长和注意力偏好各切三档，画成一张九宫格，写完一段内容就挨格核对：处在每一格里的玩家，能不能拿到他想要的东西。

刚进海滩时，不同玩家的关注点完全错开。爱考据的人能从流放者书信里摸清前因后果，对故事无感的醒来砍怪就够了，钻研机制的新手最关心的可能是第一颗技能宝石在哪儿。

反倒是刷图飞快的老玩家，路上看进去的东西经常最少。小怪还没看清长什么样就倒了，真能腾出眼神打量对手和场地的，往往只剩 Boss 战。

Matt 自己很喜欢第三幕神父 Dominus 的竞技场和台词。哪怕玩家对整段剧情毫无印象，光凭那句被社区反复提起的 The touch of God!，也能听出这神父疯得有多彻底。

装备造型和风味文本也在帮忙立住世界观。不读设定集的人也认得 Maraketh 武器的弯刃，穿过 Kaom 装备的都记得 Kaom 这号人物。甚至隔了好几年，某天了解完 Ezomyte 文化，再回头看早年戴过的头盔，才明白上面为什么把“终生服役”和“一日荣耀”刻在一起。

NPC 的零碎闲话也能起到类似作用。矿坑的 Niko 每次打招呼和道别都很短，可矿坑越挖越深，他说话的语气就越来越不对劲。哪怕从不点开他的长篇对话，光靠几次回城补给时的招呼声，也能听出他快疯了（原片 15:45–16:07）。

反面例子是修女 Cassia。刚上线时大家还挺喜欢听她哼小调，刷了几周还是反复那一段，耳朵就听腻了。后来在 48:45 的问答环节 有观众提起这事，Matt 很坦诚，直接承认当时工期太紧，来不及多录几版。

历史可以众说纷纭，眼前的事必须清楚

对爱刨根问底的玩家，Matt 反倒不赞成一上来就把世界史摊平了念。第一幕那张招工布告只写了要懂挖掘的壮丁去庄园报到，人人一眼就能看懂，爱多想的自然会多问一句：庄园底下到底在挖什么（原片 17:02）？

隐藏房间里可以放宝箱，也可以放一块只有钻进来才读得到的铭文。布告和铭文各有立场，要是突然冒出个上帝视角旁白把真相全宣布了，找线索的劲头立马泄一半。

写这类铭文时，Matt 在 23:45 分享过一个很实用的自检办法：哪怕大纲里这块石碑排第三，写的时候也要先把它当成玩家捡到的第一块。

谁也不知道玩家漏听了哪段对白、忘了上一张图读过什么，眼前这几行字本身必须说得清楚。后面的线索可以推翻你对庄园招工的猜测，但绝不能让玩家非得集齐前两块碑，才搞明白眼前这告示在招什么人。

当然，只有编剧自己心里对当年到底发生了什么一清二楚，笔下不同阵营的人才能各说各话。永恒帝国把宝石嵌进活人身体里，诗人 Victario 眼里是把人糟蹋成怪物，拿好处的贵族嘴里却成了人类进化。

Oona 找回竖琴唱起《Grand Folly》时，曲调借的还是帝王迷宫那段老旋律，歌词却完全站在 Ezomyte 人的角度写（原片 18:45–19:06）。认得出这段曲子的老玩家一听就明白，她唱的那个 Izaro，和帝国正史里供着的那位完全是两回事。

有时候连开发者在台上说漏嘴都会变成考据材料。编剧明明还不想揭晓 Kalandra 的底细，只要答观众提问时不小心吐出一个代词，社区立马记下来。

Synthesis 赛季把不可靠叙述者用得很彻底（原片 26:48）。失忆的 Cavas 拜托流放者帮他找回记忆残片，查着查着玩家才发现 Cavas 就是 Vanarius，拼出来的画面还不见得全是他自己的。

Vanarius 在严酷的体制里摸爬滚打出来，野心背后带着求生本能。他嘴上坚称世界四面受敌、只有铁腕统一才能活命，可偏偏他自己就有篡改记忆的本事。后来 Zana 作为受害者之一讲了同一段旧事，版本截然不同。你可以选择信 Zana，但就算多了这位关键证人，照样拼不出 Vanarius 完整的过去。

到了 Betrayal，纠结的对象换成了盟友 Jun。辛迪加那帮人头一次撞见流放者还很嚣张，只要被 Jun 抓去拷问过一回，下次打输了就会苦苦哀求千万别再把自己交给她。帮 Jun 查清灭门真凶合情合理，但走到审讯台前到底下不下得去手，编剧把选择权留给了玩家。

Matt 在这儿划了条很清晰的界线：瓦尔文明怎么灭的、谁该负多大责，留给社区吵上十年都没问题；可眼下为什么要替饥民找粮食、为什么要拦住 Piety 拿活人做实验，行动理由必须当场说透（原片 25:30）。

辛迪加其实也干建设、运输和研究，渗人的是他们办这些事动辄强迫别人。哪怕查出 Janus 出卖了 Jun 的组织，他跟 Catarina 究竟谁该负主责，也很难说死。好在眼前这人怎么处置由玩家说了算，就算你每次抓到俘虏都选放人，这个赛季照样玩得下去（原片 29:30–32:01）。

三条时间线同时跑，新剧本怎么不打架

赛季制游戏有个天然的别扭处：屏幕前的玩家明明记得上季帮过谁，刚建的小号却是第一天漂流到海滩。2019 年 Matt 讲起写这类长期运营游戏的剧本时，说自己脑子里得同时盯着三条时间线（原片 32:16）：

  1. 流放者本人：刚冲上海滩永远是第零天，所以 NPC 不会感谢一个新号“去年救过世界”，但这个角色亲身经历过的事可以提，比如 Cassia 会聊起他刚打完的 Innocence 结局。任务步骤也不能硬卡在低级图里，免得刷到后期的号还得折返。
  2. 屏幕前的玩家：老玩家记得前几个版本走过的终局故事。所以 3.9 更换异界终局后，世界观承认过去曾有别的流放者帮过 Zana，让老玩家陪着 Zana、Shaper 和 Elder 走过的那段历史不至于白费。
  3. 远古世界史：不同阵营对往事的看法可以打架，但底账不能自相矛盾。换个新号回头读同一块古碑，碑上记的事必须还跟以前一样。

真到了落地干活，编剧常常得从一个冷冰冰的玩法需求或者一张原画起步。策划文档里写着 三级可插入异界地图任务奖励，进游戏总得起个像样的名字，于是才有了 Watchstone。

碰上 Betrayal 这种体量就更费功夫：将近 20 个角色、2000 多句台词。每个人除了日常问候，还得看自己跟同伙处得怎么样、玩家上次是放了还是关了，随时换词。绝大部分玩家一辈子也听不全，但只要真撞上那条分支，对方就得记得上次见面发生了什么。

等进了录音棚，演员往往还能给角色加点剧本里写不出来的神韵，Matt 举的例子就是大家很熟的 Einhar（原片 37:30–37:39）。

跟美术组各自画图、最后由 Erik 统一把关不同，叙事组在 37:00 聊到协作方式 时说，他们会把玩法设计和剧本放进同一份文档里，花好几周来回磨，再由 Matt 对着旧设定一行行查重。

新稿要是跟老设定打架，多半改新稿。当然也有破例推翻旧设定的，比如新手海滩的老熟人 Hillock，他的身世前后改了好几回，直到放进辛迪加才算定型。

2019 年现场有观众问，能不能多来点像 Synthesis 那样边砍怪边听的故事。Matt 提起了 46:46 聊到的燃烧村庄信件：村口一点开朗读就能继续往前冲，等你穿过火场、把路上的怪清完，语音差不多刚好念到落款。玩家不用傻站着听，编剧反而敢把这封信写长一点。

聊到当时还叫 4.0 的二代，Matt 说故事往后拨了二十年，一代那些弑神的流放者已经成了传说，新主角得从护住弱者、找口饭吃干起。后面会不会又一路升级打到拯救世界？他笑着说自己更喜欢写普通人的挣扎，但这事不敢一个人打包票（原片 47:31）。

按 2019 年那会儿的框架，主角的远行串起整部战役，每一幕当地人的纠葛尽量当场结清。一代习惯让流放者后半程故地重游，看多年后的沧桑；二代更希望你临走前就能亲眼看见自己帮上的忙，比如 Oona 拿回竖琴，营地里立刻飘起乐声，居民敢出门找吃的，也就不再挨饿（原片 39:45–40:16）。

四年后再聊，NPC 终于能跟着一起出城了

到了 2023 年的 ExileCon，KittenCatNoodle 访谈 Matt 时聊了不少筹备二代的幕后。Matt 透了个底：光是主线大纲，团队前后就写了大约 40 份，经常花一两天搭好骨架，看看不对味又推倒重来。

2019 年放出来试玩的第一幕改动不算大，后面几幕当时还有一大堆没敲定。等到 2023 年，第二、三、四幕都有了能上手的实机演示。虽然换了一批新职业，脚底下还是巨兽倒下、神明陨落之后那片土地。预告片里那个亲历者讲起当年神明归来的惨状，对他来说那就是自己实打实熬过来的二十年（原片 7:08:01）。

Matt 自己的担子在这四年里也重了。早先他基本只管二代，偶尔抽空帮一代写写试炼大师和 Maven，一代的常规赛季归别的编剧写。到 2023 年，两边的剧本都过他手，虽然更忙，好处也很实在：写一代新赛季时能多留个心眼，核对和二代的设定对不对得上，有时候还能提前埋伏笔（原片 7:09:00）。

二代塑造角色的不少做法，其实是先在一代练过手的。Betrayal 和 Heist 都让不同编剧分头认领角色，说话口吻一下子拉开了差距。Heist 里队友一路拌嘴，玩家跑图就听完了，不用站桩聊天。不过要论偏爱，Matt 还是最喜欢 Synthesis，因为从立项第一天起，大家就在一起想玩家怎么找回记忆、找回来的究竟是谁的人生。

发布会前夕刚公布了 Trial of the Ancestors 赛季。Matt 说那前一个月团队一口气给 20 多位 角色录了音，其中 11 位 还是最后一周半赶着给新赛季录完的。清一色都是卡鲁族长，怎么让玩家闭着眼也能听出谁是谁，挺费心思（原片 7:10:15–7:10:44）。

被问到 Harbinger 以后还有没有后续时，Matt 拿 7:18:46 聊到的 Navali 回归 举了个例子：老面孔回来可以，但玩法得跟以前拉开足够大的差距，免得当年不喜欢 Prophecy 的玩家一看她就犯怵，以为又得重温旧梦。

另外，会场里提供的移动版演示特意把时间定在二十年前，正好拿来补写正传时间线上插不进去的旧事，里头还藏了个呼应 Synthesis 的彩蛋（原片 7:13:15）。

二代里，NPC 不再一直待在营地里站桩说话。玩家头一回碰见 Asala 是在古门外，两人二话不说先一起杀出去，至于她什么来头，等进了城有空再慢慢问。

第二幕的说书人 Zarka 则是给爱听故事的人准备的，到访谈那天已经录了四五轮、攒下快 50 页 对白。只想狂奔推主线的玩家完全可以无视她（原片 7:14:15）。

Alva 用上的机制更直接：让最对口的 NPC 直接出现在事件现场（原片 7:16:46）。玩家一脚踏进瓦尔遗迹，研究瓦尔的 Alva 就站在旁边，趁着眼前的机关和壁画当场开讲。走到第三幕城镇、第四幕开篇，还会再撞见她，这比打完副本再回营地听人追忆刚才发生了什么自然得多。

聊到 Alva，KittenCatNoodle 没忍住，把社区猜了多年的老悬念抛了出来：Alva 到底是不是那位“最后死去的人”？Matt 脱口而出“这不是很明显嘛”，还补了一句两人的配音和模型压根就是同一个（原片 7:18:00）。

主持人当场一愣：“官方以前可从来没盖章过啊！”Matt 这才反应过来，笑着往回圆了句“也别全信台上这家伙的话”。不过聊完辨认线索，至于 Alva 到底怎么穿越的时间，他嘴还是守得很紧。

到了二代，连一路跳过对白或者干脆不理人都被写进了反馈里（原片 7:25:00–7:25:16）：

  • 没接委托就把活儿干完了，NPC 会纳闷你是怎么摸到那儿的，Zarka 甚至会数落你光知道埋头打架。
  • 要是整整一幕你都没跟某个人搭过腔，等到幕尾突然凑上去，人家干脆就不认识你，不过该给的奖励一分不少。
  • 不同职业和当地族群原本就有宿怨或渊源，走在同一条街上，有的职业受欢迎，有的就得吃闭门羹。

聊起自己偏爱写的人物关系，Matt 提了两种（原片 7:24:00–7:24:45）：

  • 像一代的 Piety，明摆着是死对头，偏偏一时半会儿杀不了她。
  • 你尽心尽力帮完一个人，事后才开始犯嘀咕：他手里真有了权，会不会也变成下一个恶人？

一代里有过把羽毛交给谁、决定谁来掌权的分岔。Matt 觉得二代要是再把这种选择交给玩家，就得让人真看见是谁上了台、当地后来变成了什么样。

被问到 Maven 的故事还有没有下文时，Matt 笑着说自己也想给她一个交代。他平时和 Jonathan 过剧本，习惯把三件事拆开琢磨：主角想干什么、NPC 为什么这么干，以及屏幕前那个活生生的人实际上会往哪儿乱跑（原片 7:26:45）。回头再看当年那 23 个 救蒙面人的任务状态，也就很能理解他的顾虑了。
